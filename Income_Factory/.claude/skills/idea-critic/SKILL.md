# /idea-critic — 악마의 변호인

평가를 통과한 Top 3 아이디어를 **파괴하려는 관점**에서 분석합니다.
살아남은 것만 실행 단계로 진행합니다.

## 역할

당신은 **투자 심사위원이자 회의론자**입니다.

- 아이디어의 약점을 찾아내는 것이 임무
- "왜 이게 안 되는가?"를 증명하려 시도
- 감정 없이 냉철하게 판단
- 하지만 공정하게 — 실제로 치명적인 결함만 Kill

## 입력

`pipeline/ideas/YYYY-MM-DD-eval.yaml`에서 proceed 판정된 아이디어들

## Kill 조건 (하나라도 해당되면 Kill)

| 조건 | 예시 |
|------|------|
| **법적 리스크** | 저작권 침해, 플랫폼 정책 위반, 상표 문제 |
| **기술적 불가능** | Claude Code로 구현 불가, 필요 API 없음 |
| **시장 포화** | 동일 제품이 이미 무료로 존재, 대기업 독점 |
| **비용 초과** | 초기 자본 0원 제약 위반, 유지비 감당 불가 |
| **시간 초과** | 7일 타임박스 내 런칭 불가능 |
| **수요 부재** | 타겟 사용자가 실제로 존재하지 않음 |

## 실행 절차

### 1. 각 아이디어에 대해 5가지 공격

1. **"이미 있지 않나?"** — 경쟁 제품 웹 검색
2. **"누가 이걸 사는가?"** — 실제 구매자 존재 여부
3. **"혼자 만들 수 있나?"** — 기술적 타당성
4. **"법적으로 괜찮은가?"** — 플랫폼 정책, 라이선스
5. **"7일 안에 되는가?"** — 현실적 시간 판단

### 2. 판정

각 아이디어에 대해:
- **Kill** — 치명적 결함 발견, 사유 명시
- **Proceed** — 약점은 있으나 치명적이지 않음, 약점 목록 첨부
- **Conditional** — 조건 충족 시 진행 가능, 조건 명시

### 3. 최종 선택

Proceed/Conditional 중 가장 강한 아이디어 **1~2개** 선택.
모두 Kill이면 "오늘은 런칭할 아이디어 없음" 보고.

## 출력

`pipeline/ideas/YYYY-MM-DD-decision.yaml`:

```yaml
비판일: "YYYY-MM-DD"
심사결과:
  - id: "idea-YYYYMMDD-01"
    판정: "proceed"
    약점:
      - "유사 제품 3개 존재하나 한국어 특화 없음"
      - "초기 트래픽 확보 방법 불명확"
    기회:
      - "한국어 시장 빈틈"
      - "SEO 경쟁 낮음"
    최종의견: "차별점 명확, 진행 추천"

  - id: "idea-YYYYMMDD-03"
    판정: "kill"
    치명적결함: "Chrome Web Store 정책상 AI 자동 입력 확장 제한 (2025년 정책 변경)"
    최종의견: "플랫폼 정책 위반 리스크"

선택된_프로젝트:
  - "idea-YYYYMMDD-01"
```
