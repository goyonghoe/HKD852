🎯 CTO (Chief Technology Officer)

역할

  • 사용자 요청 분석 및 작업 유형 파악
  • 적절한 팀에 작업 위임
  • 진행 상황 모니터링
  • 최종 결과물 검증 및 보고

의사결정 원칙

  • ✅ 자율성: 팀에 권한 위임
  • ⚡ 효율성: 병렬 처리
  • 🎯 품질 우선: 속도보다 품질
  • 💬 명확한 소통: 진행 상황 보고

🎨 Art Team Lead

팀원들

  • Art Spec Manager
    명세서 구조 설계 및 생성
    카테고리별 자동 생성
  • Visual Curator
    참고 이미지 큐레이션
    Google Drive 관리
  • Resource Coordinator
    리소스 분류 및 매핑
    파일명 패턴 생성

작업 프로세스

  1. CTO로부터 요청 받음
  2. 팀원에게 작업 분배
  3. 진행 상황 확인
  4. 품질 자체 체크
  5. QA Team에 리뷰 요청
  6. CTO에 완료 보고

✅ QA Team Lead

팀원들

  • Image Validator: 이미지 규격 자동 검증
    → 사이즈, 포맷, 색상 모드, 파일 크기
  • Review Specialist: 명세서 데이터 검증
    → 일관성, 필수 필드, 멤버 순서

품질 기준

Critical
  • 이미지 사이즈
  • 필수 데이터
  • 파일 포맷
High
  • 색상 모드
  • 파일 크기
  • 멤버 순서
Medium
  • 파일명 일관성
  • 참고 이미지
  • 용도 설명

💾 Data Manager

  • 멤버 목록 조회
  • 참고 이미지 정보

⚡ 조회 속도: 즉시 (<100ms)

🎯 정확도: 100%

⚙️ 실제 작동 방식

예시: MEOVV 한정테마 명세서 생성

1. 사용자 요청

/ssbl-cto MEOVV MY EYES OPEN VVIDE 앨범 한정테마 명세서 생성해줘

2. CTO 분석 및 위임

  • 카테고리: 한정테마 포토카드 업데이트
  • 아티스트: MEOVV
  • 앨범: MY EYES OPEN VVIDE

→ Art Team Lead에게 위임

3. Art Team 작업

  • Data Manager에서 MEOVV 정보 조회 (5멤버)
  • Art Spec Manager가 명세서 생성
  • Visual Curator가 참고 이미지 추가
  • Resource Coordinator가 리소스 매핑

4. QA Team 검증

  • Image Validator: 이미지 규격 검증
  • Review Specialist: 데이터 일관성 체크

5. CTO 최종 보고

✅ 생성 완료: 한정테마포토카드업데이트_MEOVV_MYEYESOPENVVIDE.csv

📊 생성되는 명세서

3개 섹션으로 구성

1️⃣ 시각 참고 자료

카테고리별 화면 예시
Google Drive 링크

2️⃣ 일감 기본 정보

아티스트, 멤버, 앨범
발매일, 경로 등

3️⃣ 리소스 체크리스트

리소스별 사이즈, 파일명

멤버별 자동 확장

그룹 아티스트의 경우 멤버 수만큼 자동으로 행 생성

예: MEOVV (5멤버) → 포토카드 5개 행 자동 생성

💼 실제 사례

요청: /ssbl-cto MEOVV MY EYES OPEN VVIDE 앨범 한정테마 명세서 생성해줘

처리 과정:

  1. Layer2 CSV에 리소스 데이터 5개 추가 (한정테마 관련)
  2. MEOVV 아티스트 정보 조회 (5멤버)
  3. MY EYES OPEN VVIDE 앨범 정보 조회
  4. 명세서 자동 생성 (멤버별 확장)
  5. 총 26개 리소스 항목 생성

결과: ✅ 한정테마포토카드업데이트_MEOVV_MYEYESOPENVVIDE.csv

소요 시간: 약 2분
