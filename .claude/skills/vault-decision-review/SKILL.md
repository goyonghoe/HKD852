# vault-decision-review

의사결정 패턴 분석 스킬. Obsidian Vault의 결정 기록, 회의록, 데일리 노트에서 의사결정 패턴을 추출하고 인사이트를 생성한다.

## 상수

- `VAULT_ROOT`: `/Users/yong/MainFolder/My_AI_Project/HKD852_Vault`
- 출력 파일: `$VAULT_ROOT/03_Decisions/_패턴분석.md`

## 인자

- 기간 지정 시 해당 기간만 분석 (예: "2026-03", "2026-02~2026-03", "최근 1개월")
- 생략 시 전체 기간 분석

## 절차

### 1단계: 결정 노트 수집

```
Glob: $VAULT_ROOT/03_Decisions/*.md
```

- `_패턴분석.md` 자체는 분석 대상에서 제외
- 각 노트에서 추출할 정보:
  - 제목/주제
  - 날짜 (frontmatter `date` 또는 파일명)
  - 프로젝트 (tags 또는 본문에서 추론)
  - 결정 상태 (확정/미결/번복)
  - 결정 유형 (기술/비즈니스/인사/프로세스)
  - 결정 소요 시간 (최초 논의일 ~ 확정일)

### 2단계: 회의록에서 결정 관련 내용 탐색

```
Grep: pattern="결정|확정|fix|승인|결론|합의"
      path=$VAULT_ROOT/02_Meetings/
```

- 회의에서 내려진 결정을 1단계 결과와 매핑
- 회의 기반 결정 vs 단독 결정 구분

### 3단계: 데일리 노트에서 결정 관련 엔트리 탐색

```
Grep: pattern="결정|확정|승인|보류|미결"
      path=$VAULT_ROOT/01_Daily/
```

- 데일리 노트에 언급된 결정 사안 추가 수집
- 미결 사안 식별

### 4단계: 패턴 분석

수집된 데이터를 기반으로 아래 항목 분석:

- **총 결정 수**: 전체 및 프로젝트별
- **결정 속도**: 당일 결정, 1주 이상 지연, 미결 상태
- **결정 유형 분포**: 기술/비즈니스/인사/프로세스
- **패턴 인사이트**:
  - 어떤 유형의 결정을 빠르게/느리게 하는가
  - 혼자 결정 vs 회의에서 결정 비율
  - 번복된 결정 유무 및 사유
- **권고**: 미결 사안 리마인드, 프로세스 개선 제안

### 5단계: 보고서 생성

`$VAULT_ROOT/03_Decisions/_패턴분석.md`에 아래 형식으로 작성:

```markdown
---
date: "YYYY-MM-DD"
type: decision-analysis
tags: [decision, analysis, auto-generated]
---

# 의사결정 패턴 분석

> 마지막 분석: YYYY-MM-DD

## 총 결정 수
- 기록된 결정: N건
- 프로젝트별: SSBL N건, WanChai N건, ...

## 결정 속도 분석
- 빠른 결정 (당일): N건
- 지연된 결정 (1주+): N건 — 목록
- 미결 상태: N건 — 목록 (⚠️ 주의)

## 결정 유형 분포
- 기술적 결정: N건
- 비즈니스 결정: N건
- 인사 결정: N건
- 프로세스 결정: N건

## 패턴 인사이트
- (어떤 유형의 결정을 빨리/느리게 하는가)
- (혼자 결정 vs 회의에서 결정)
- (번복된 결정이 있는가)

## 권고
- (미결 사안 리마인드)
- (개선 제안)
```

## 주의사항

- 날짜가 없는 결정 노트는 파일 수정일 기준으로 처리
- 기간 필터 적용 시 frontmatter `date` 우선, 없으면 파일명에서 날짜 추출
- 기존 `_패턴분석.md`가 있으면 덮어쓰기 (매 실행마다 전체 재분석)
