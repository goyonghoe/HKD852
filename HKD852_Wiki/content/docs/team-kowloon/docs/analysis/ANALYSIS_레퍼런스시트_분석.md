# 레퍼런스 시트 분석 및 개선 방안

## 📋 현재 구현 vs 레퍼런스 비교

### 현재 구현 (generate_album_sheets)

```
헤더 (4줄) + 단일 테이블
├─ 카테고리: {category}
├─ 앨범: {artist} - {album}
├─ 생성일: {date}
├─ 총 리소스: {count}개
└─ [테이블]
   └─ 컬럼: 리소스 타입, 규격, 파일 형식, 게임 내 위치, 규격 설명,
            체크리스트, 주의사항, 참고 자료, 담당자, 상태, 완성도, 다음 액션
   └─ 행: 리소스당 1행
```

### 레퍼런스 구조 (신규앨범 ADP, 한정테마 ADP)

```
1-49줄: 헤더 섹션 (이미지 삽입용 빈 공간)
  ├─ 타이틀: [SSBL / 신규 앨범] 아트 작업 요청 가이드
  ├─ 포토카드 기본 규격 및 결과물 예시 (이미지 영역)
  └─ 인게임 적용 예시 (이미지 영역)

50-61줄: [신규 앨범] 일감 기본 정보
  ├─ 구분 | 내용
  ├─ 앨범 코드 | (입력 필요)
  ├─ 일감 구분 | ALLDAY PROJECT - ALLDAY PROJECT 신규 앨범
  ├─ 아티스트 이름 | ALLDAY PROJECT
  ├─ 멤버 (순서 고정) | ANNIE, TARZZAN, BAILEY, WOOCHAN, YOUNGSEO
  ├─ 앨범 구분 | ALLDAY PROJECT
  ├─ 엠블럼 이미지 경로 | (입력 필요)
  ├─ 원본 리소스 경로 | (입력 필요)
  ├─ 제작 리소스 저장 경로 | (입력 필요)
  └─ 이미지 제작 시 참고 사항 | -

62-76줄: [신규 앨범 리소스 제작 체크리스트]
  ├─ 컬럼: 리소스 구분 | 구분 | 사이즈 | 파일명 | (작업 완료) | (비고)
  ├─ 일반 테마 포토카드 초상 | ANNIE | 380x512 | Image_Card_{code}
  ├─ 일반 테마 포토카드 초상 | TARZZAN | 380x512 | Image_Card_{code}
  ├─ 일반 테마 포토카드 초상 | BAILEY | 380x512 | Image_Card_{code}
  ├─ ... (각 멤버별 행)
  ├─ 프로필 이미지 | ANNIE | 128x128 | Image_Profile_{code}
  ├─ ... (각 멤버별 행)
  ├─ 앨범 커버 이미지 | - | 512x512 | Image_Album_{code}
  ├─ 엠블럼 이미지 | - | ~280x40 | Image_Group_{code}
  └─ 배경 이미지 | - | 1280x1280 | Image_LobbyBg_{code}
```

## 🎯 핵심 차이점

### 1. **구조적 차이**

| 항목        | 현재                | 레퍼런스                        | 변경 필요 |
| ----------- | ------------------- | ------------------------------- | --------- |
| 섹션 구분   | 없음 (단일 테이블)  | 3개 섹션 (헤더/정보/체크리스트) | ✅ 필수   |
| 멤버별 확장 | 없음 (리소스당 1행) | 있음 (멤버당 1행)               | ✅ 필수   |
| 이미지 영역 | 없음                | 49줄 (삽입 공간)                | ⚠️ 선택   |
| 파일명 규칙 | 없음                | Image*Card*{code} 등            | ✅ 필수   |

### 2. **데이터 구조 차이**

| 항목           | 현재        | 레퍼런스             |
| -------------- | ----------- | -------------------- |
| **컬럼 수**    | 12개        | 4-6개 (섹션별 다름)  |
| **행 수**      | 리소스 개수 | 멤버별 확장 (5-20배) |
| **메타데이터** | 상단 4줄    | 별도 섹션 10줄       |

### 3. **컬럼 매핑**

#### 현재 구현

- 리소스 타입, 규격, 파일 형식, 게임 내 위치, 규격 설명, 체크리스트, 주의사항, 참고 자료, 담당자, 상태, 완성도, 다음 액션

#### 레퍼런스 (체크리스트 섹션)

- **리소스 구분**: 현재의 "리소스 타입" (예: 일반 테마 포토카드 초상)
- **구분**: 멤버명 또는 "-" (예: ANNIE, TARZZAN, -)
- **사이즈**: 현재의 "규격" (예: 380x512)
- **파일명**: 새로 추가 (예: Image*Card*{code})
- **작업 완료**: 새로 추가 (TRUE/FALSE, 기본값 FALSE)
- **비고**: 한정테마에만 있음 (선택)

## 💡 개선 방안 제안

### A안: 레퍼런스 완전 준수 (추천)

**장점:**

- 유저가 제공한 레퍼런스와 100% 일치
- 멤버별 작업 배분 명확
- 파일명 규칙 명시로 혼란 방지
- Google Sheets에서 체크박스 활용 가능 (작업 완료 컬럼)

**단점:**

- 멤버 정보 매핑 필요 (아티스트별 멤버 리스트)
- 행 수 증가 (5배~20배)
- 현재 구현의 풍부한 정보 (체크리스트, 주의사항, 다음 액션 등) 제거

**구현 변경사항:**

1. **멤버 매핑 데이터 추가**

   ```python
   ARTIST_MEMBERS = {
       "ALLDAY PROJECT": ["ANNIE", "TARZZAN", "BAILEY", "WOOCHAN", "YOUNGSEO"],
       "TAEYANG": [],  # 솔로 아티스트는 빈 리스트
       # ... 기타 아티스트
   }
   ```

2. **3섹션 구조로 재구성**
   - 1-49줄: 헤더 (이미지 placeholder)
   - 50-60줄: 일감 기본 정보 (메타데이터)
   - 61줄~: 리소스 제작 체크리스트 (멤버별 확장)

3. **파일명 규칙 매핑**

   ```python
   FILENAME_PATTERNS = {
       "포토카드 초상": "Image_Card_{code}",
       "프로필 이미지": "Image_Profile_{code}",
       "앨범 커버": "Image_Album_{code}",
       "엠블럼": "Image_Group_{code}",
       "배경": "Image_LobbyBg_{code}",
       # ... 기타
   }
   ```

4. **컬럼 변경**
   - 기존 12개 컬럼 → 4-6개 컬럼
   - 작업 완료 컬럼 추가 (FALSE 기본값)

### B안: 하이브리드 (레퍼런스 구조 + 현재 정보 유지)

**장점:**

- 레퍼런스의 명확한 구조 + 현재의 풍부한 정보
- 작업 지시사항이 더 상세함
- 한 시트에서 모든 정보 확인 가능

**단점:**

- 컬럼 수가 많아짐 (10개 이상)
- Google Sheets에서 가로 스크롤 필요
- 레퍼런스와 정확히 일치하지 않음

**구현 변경사항:**

- A안과 동일하지만 컬럼 추가:
  - 리소스 구분 | 구분 | 사이즈 | 파일명 | **파일 형식** | **체크리스트** | **주의사항** | **담당자** | 작업 완료 | **완성도** | **다음 액션** | 비고

### C안: 별도 시트 분리

**장점:**

- 작업자용 시트 (레퍼런스 방식) + 관리자용 시트 (현재 방식) 병행
- 각각의 목적에 맞는 최적 포맷
- 정보 손실 없음

**단점:**

- 시트 개수 2배
- 데이터 동기화 이슈 가능성

## ✅ 최종 추천: **A안 + α**

**기본은 A안 (레퍼런스 완전 준수)를 따르되, 다음 개선사항 추가:**

1. **#Constant 시트 자동 생성**
   - ref_Constant.csv처럼 전체 리소스 타입별 규격 정리
   - 모든 프로젝트에서 참조 가능한 마스터 시트

2. **코드 생성 규칙 정의**
   - `{code}` placeholder를 실제 코드로 변환 가능하게
   - 예: ADP_ALBUM01_ANNIE_001 → Image_Card_ADP_ALBUM01_ANNIE_001

3. **경로 정보 자동 생성**
   - Google Drive 폴더 구조 제안
   - 예: `/SSBL/Art/신규앨범/ALLDAY_PROJECT/원본/`, `/SSBL/Art/신규앨범/ALLDAY_PROJECT/완성/`

4. **카테고리별 템플릿 차별화**
   - 신규앨범: ref\_신규앨범\_ADP.csv 템플릿
   - 한정테마: ref\_한정테마\_ADP.csv 템플릿
   - 각각 필요한 리소스 타입만 포함

## ❓ 결정이 필요한 사항

1. **멤버 정보를 어떻게 가져올까요?**
   - ① CSV에 멤버 컬럼 추가 (수동 입력)
   - ② 별도 매핑 파일 생성 (아티스트 → 멤버 리스트)
   - ③ API나 데이터베이스에서 가져오기

2. **헤더 이미지 영역 (1-49줄)을 어떻게 처리할까요?**
   - ① CSV에 빈 행 49개 삽입 (수동으로 이미지 추가)
   - ② URL placeholder 삽입 (나중에 이미지 URL로 교체)
   - ③ 생략하고 바로 정보 섹션부터 시작

3. **코드 생성 규칙은?**
   - ① {code} 그대로 유지 (수동 입력 필요)
   - ② 자동 생성: `{artist}_{album}_{member}_{sequence}`
   - ③ 별도 코드 매핑 파일 사용

4. **현재의 풍부한 정보 (체크리스트, 주의사항, 다음 액션)를 어떻게 처리할까요?**
   - ① 완전 제거 (레퍼런스와 정확히 일치)
   - ② 비고 컬럼에 요약해서 포함
   - ③ 별도 시트로 분리
