# 데이터 흐름 매핑 (/data-flow)

> HKD852 프로젝트의 외부 서비스 연결을 매핑하고, 데이터 흐름별 리스크 등급을 부여합니다.

## 역할

- 코드베이스 내 외부 서비스 호출 식별 및 매핑
- 핵심 다이어그램 2종: ① Anthropic 서버행 데이터 ② 웹 공개 데이터
- 각 데이터 흐름에 리스크 등급 부여
- `/threat-model` 입력 데이터로 활용

## 실행 절차

### Step 1: 외부 서비스 식별

`Grep`과 `Glob`으로 코드베이스에서 외부 서비스 연결점을 탐색합니다:

#### 1-1. 알려진 HKD852 외부 서비스

| 서비스         | 검색 패턴                           | 예상 데이터          |
| -------------- | ----------------------------------- | -------------------- |
| Anthropic API  | `anthropic`, `claude`, `sk-ant-`    | 프롬프트, 코드, 문서 |
| Vercel         | `vercel`, `VERCEL_`                 | 빌드 결과, 환경변수  |
| Neon DB        | `neon`, `postgres`, `DATABASE_URL`  | 사용자 데이터, 결제  |
| GitHub         | `github`, `gh`, `GITHUB_`           | 소스코드, 이슈       |
| YouTube API    | `youtube`, `googleapis.com/youtube` | 메타데이터, 업로드   |
| Naver API      | `naver`, `openapi.naver`            | 주식 데이터          |
| Google TTS     | `texttospeech`, `tts`               | TTS 텍스트           |
| Slack          | `slack`, `xoxb-`, `xoxp-`           | 메시지, 알림         |
| Jira           | `jira`, `atlassian`                 | 태스크, 코멘트       |
| OpenRouter     | `openrouter`                        | AI 프롬프트          |
| KRX/한국거래소 | `krx`, `kind.krx`                   | 시장 데이터          |
| PortOne/Toss   | `portone`, `toss`, `imp_`           | 결제 정보            |

### Step 2: 데이터 흐름 분류

각 서비스 연결에 대해 데이터 흐름을 분류합니다:

| 분류          | 설명                 | 예시                    |
| ------------- | -------------------- | ----------------------- |
| OUTBOUND      | HKD852 → 외부 서비스 | API 호출, 데이터 업로드 |
| INBOUND       | 외부 서비스 → HKD852 | API 응답, 웹훅          |
| BIDIRECTIONAL | 양방향               | WebSocket, DB 연결      |
| PUBLIC        | HKD852 → 인터넷 공개 | 웹 배포, 공개 API       |

### Step 3: 다이어그램 1 — Anthropic 서버행 데이터

Claude Code 세션에서 Anthropic 서버로 전송되는 데이터를 매핑합니다:

```
┌─────────────────────────────────────────────────┐
│               HKD852 로컬 환경                   │
│                                                  │
│  ┌──────────┐    ┌──────────────┐               │
│  │ 소스코드 │───→│ Claude Code  │               │
│  └──────────┘    │  세션        │               │
│  ┌──────────┐    │              │    ┌─────────┐│
│  │ 설정파일 │───→│ .claudeignore├───→│ BLOCKED ││
│  └──────────┘    │ 필터링       │    └─────────┘│
│  ┌──────────┐    │              │               │
│  │ 데이터   │───→│              │               │
│  └──────────┘    └──────┬───────┘               │
│                         │                        │
└─────────────────────────┼────────────────────────┘
                          │ (허용된 데이터만)
                          ▼
               ┌──────────────────┐
               │ Anthropic 서버   │
               │ (API 처리)       │
               └──────────────────┘
```

**점검 항목**:

- `.claudeignore`에 의해 차단되는 파일/폴더 목록
- `security-guard.sh` hook에 의해 차단되는 패턴
- 차단되지 않고 전송 가능한 파일 중 민감 데이터 포함 여부

### Step 4: 다이어그램 2 — 웹 공개 데이터

Vercel 등에 배포되어 인터넷에 공개되는 데이터를 매핑합니다:

```
┌─────────────────────────────────────────────────┐
│                 Vercel 배포 앱                    │
│                                                  │
│  ┌─────────┐  ┌──────────┐  ┌────────────────┐ │
│  │ public/ │  │ API 라우트│  │ 클라이언트 번들│ │
│  │ (정적)  │  │ (동적)   │  │ (JS 번들)     │ │
│  └────┬────┘  └────┬─────┘  └──────┬─────────┘ │
│       │            │               │             │
└───────┼────────────┼───────────────┼─────────────┘
        │            │               │
        ▼            ▼               ▼
   ┌─────────────────────────────────────┐
   │           인터넷 (공개)              │
   │  누구나 접근 가능                    │
   └─────────────────────────────────────┘
```

**점검 항목**:

- 각 배포 앱별 public 폴더 내용
- API 라우트 응답에 포함되는 데이터
- 클라이언트 사이드 코드에 하드코딩된 데이터

### Step 5: 리스크 등급 부여

각 데이터 흐름에 리스크 등급을 부여합니다:

| 리스크 등급 | 기준                                 |
| ----------- | ------------------------------------ |
| CRITICAL    | PII/시크릿이 비인가 경로로 전송/공개 |
| HIGH        | 민감 비즈니스 데이터가 외부 전송     |
| MEDIUM      | 비민감 데이터지만 암호화 미적용      |
| LOW         | 공개 데이터 또는 적절히 보호된 경로  |
| INFO        | 정보 제공용 (리스크 없음)            |
