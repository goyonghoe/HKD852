# 위협 모델링 (/threat-model)

> STRIDE 프레임워크를 적용하여 HKD852 시스템의 위협을 체계적으로 분석합니다.
> `/data-flow` 산출물을 참조하여 데이터 흐름 기반 위협을 도출합니다.

## 역할

- STRIDE 6관점 위협 분석 (Spoofing, Tampering, Repudiation, Information Disclosure, Denial of Service, Elevation of Privilege)
- `/data-flow` 산출물 기반 위협 시나리오 도출
- 위협별 영향도 및 대응 방안 제시
- 경량 구현 (핵심 위협에 집중, 향후 확장 가능)

## 실행 절차

### Step 1: 대상 시스템 파악

대상: `$ARGUMENTS` (미지정 시 전체 시스템)

#### 1-1. `/data-flow` 산출물 확인

`Glob`으로 기존 데이터 흐름 분석 결과를 확인합니다:

- `Shield_Agent/outputs/data_flow_*.md`
- 없으면 주요 외부 서비스와 데이터 경로를 직접 파악

#### 1-2. 시스템 경계 식별

| 경계            | 구성 요소                          |
| --------------- | ---------------------------------- |
| 사용자 ↔ 웹앱   | 브라우저, Vercel 배포 앱           |
| 웹앱 ↔ DB       | Next.js API Routes ↔ Neon Postgres |
| 웹앱 ↔ 외부 API | Anthropic, YouTube, Naver, KRX 등  |
| 개발자 ↔ Claude | Claude Code 세션 ↔ Anthropic 서버  |
| CI/CD ↔ 배포    | GitHub → Vercel                    |

### Step 2: STRIDE 분석

각 시스템 경계에 대해 6가지 위협 관점을 적용합니다:

#### S — Spoofing (위장)

> "누군가 다른 사람/시스템인 척 할 수 있는가?"

| 점검 항목                              | 대상 경계       |
| -------------------------------------- | --------------- |
| 인증 없이 API 호출 가능 여부           | 웹앱 ↔ DB       |
| 세션 토큰 탈취 가능 여부               | 사용자 ↔ 웹앱   |
| API 키 없이 외부 서비스 호출 가능 여부 | 웹앱 ↔ 외부 API |
| Git 커밋 위장 (서명 미적용) 여부       | CI/CD ↔ 배포    |

#### T — Tampering (변조)

> "데이터를 무단으로 변경할 수 있는가?"

| 점검 항목                                       | 대상 경계     |
| ----------------------------------------------- | ------------- |
| 클라이언트 사이드 데이터 변조 (게임 점수, 결제) | 사용자 ↔ 웹앱 |
| API 요청 파라미터 변조                          | 사용자 ↔ 웹앱 |
| DB 데이터 직접 조작 가능 여부                   | 웹앱 ↔ DB     |
| 배포 파이프라인 변조                            | CI/CD ↔ 배포  |

#### R — Repudiation (부인)

> "행위를 부인할 수 있는가? 감사 추적이 가능한가?"

| 점검 항목                       | 대상 경계       |
| ------------------------------- | --------------- |
| 결제/거래 로그 존재 여부        | 사용자 ↔ 웹앱   |
| API 호출 로그 기록 여부         | 웹앱 ↔ 외부 API |
| 관리자 행위 감사 로그 여부      | 전체            |
| 데이터 변경 이력 추적 가능 여부 | 웹앱 ↔ DB       |

#### I — Information Disclosure (정보 노출)

> "민감 정보가 비인가자에게 노출될 수 있는가?"

| 점검 항목                                     | 대상 경계       |
| --------------------------------------------- | --------------- |
| 코드베이스 → Anthropic 서버 전송 (PII/시크릿) | 개발자 ↔ Claude |
| public/ 폴더 민감 데이터                      | 사용자 ↔ 웹앱   |
| 에러 메시지 내부 정보 노출                    | 사용자 ↔ 웹앱   |
| API 응답 과다 정보 반환                       | 웹앱 ↔ DB       |
| 로그 파일 민감 데이터 포함                    | 전체            |

#### D — Denial of Service (서비스 거부)

> "서비스를 마비시킬 수 있는가?"

| 점검 항목                         | 대상 경계     |
| --------------------------------- | ------------- |
| API 레이트 리밋 미적용            | 사용자 ↔ 웹앱 |
| 대용량 파일 업로드 제한 미설정    | 사용자 ↔ 웹앱 |
| DB 쿼리 타임아웃 미설정           | 웹앱 ↔ DB     |
| Vercel 무료 플랜 제한 초과 가능성 | CI/CD ↔ 배포  |

#### E — Elevation of Privilege (권한 상승)

> "일반 사용자가 관리자 권한을 획득할 수 있는가?"

| 점검 항목                            | 대상 경계     |
| ------------------------------------ | ------------- |
| 역할 기반 접근 제어 (RBAC) 구현 여부 | 웹앱 ↔ DB     |
| 관리자 API 노출 여부                 | 사용자 ↔ 웹앱 |
| 환경변수/설정 변경 권한 제한 여부    | CI/CD ↔ 배포  |
| 클라이언트 사이드 역할 판단 여부     | 사용자 ↔ 웹앱 |

### Step 3: 위협 등급 산정

각 위협에 DREAD 모델로 영향도를 산정합니다:

| 요소             | 1 (Low)   | 2 (Medium) | 3 (High) |
| ---------------- | --------- | ---------- | -------- |
| Damage Potential | 경미      | 중간       | 심각     |
| Reproducibility  | 어려움    | 조건부     | 쉬움     |
| Exploitability   | 전문 지식 | 일부 지식  | 누구나   |
| Affected Users   | 소수      | 일부       | 전체     |
| Discoverability  | 어려움    | 검색 가능  | 명백     |

**총점**: 5~15 → LOW(5-7) / MEDIUM(8-10) / HIGH(11-13) / CRITICAL(14-15)
