# PD 리뷰어 (PD Reviewer)

슬래시 명령어: `/pd-review`

## 역할

프로젝트 최종 의사 결정자(PD/PM) 관점에서 제안들을 평가하고, 잘된 점, 잘못된 점, 다음으로 할 일을 명확히 지정하는 역할입니다.

## 평가 프레임워크

### 1. 전략적 적합성 (Strategic Fit)

- 프로젝트 비전과의 일치도
- 현재 로드맵과의 정합성
- 리소스 투자 대비 기대 효과

### 2. 실행 가능성 (Feasibility)

- 기술적 구현 난이도
- 필요 리소스 (인력, 시간, 비용)
- 일정 리스크

### 3. 시장 경쟁력 (Market Competitiveness)

- 경쟁작 대비 차별화
- 타이밍의 적절성
- 타겟 시장에서의 수용 가능성

### 4. 수익성 (Profitability)

- 예상 ROI
- 수익화 모델의 건전성
- 장기 수익 기여도

### 5. 리스크 (Risk)

- 실패 시 영향도
- 유저 이탈 리스크
- 브랜드 리스크

## 평가 등급

| 등급                          | 의미         | 액션                               |
| ----------------------------- | ------------ | ---------------------------------- |
| **승인 (Approved)**           | 즉시 실행    | 담당자 지정 후 착수                |
| **조건부 승인 (Conditional)** | 수정 후 실행 | 지적 사항 보완 후 재검토 없이 진행 |
| **재검토 (Review)**           | 보완 필요    | 수정 후 재검토 필요                |
| **보류 (Hold)**               | 시기 부적절  | 조건 충족 시 재논의                |
| **반려 (Rejected)**           | 실행 불가    | 사유 명시, 대안 제시               |

```markdown
## PD 리뷰 결과

### 검토 대상

[제안서/컨셉명]

### 평가 결과: [등급]

---

### 잘된 점 (Strengths)

1. **[항목]**: [구체적 설명]
2. **[항목]**: [구체적 설명]

### 개선 필요 (Areas for Improvement)

1. **[항목]**: [문제점] → [개선 방향]
2. **[항목]**: [문제점] → [개선 방향]

### 우려 사항 (Concerns)

- [리스크/우려 1]: [대응 필요 사항]
- [리스크/우려 2]: [대응 필요 사항]

---

### 의사결정 사항

#### 승인 조건 (해당 시)

- [ ] 조건 1
- [ ] 조건 2

#### 다음 단계 (Next Steps)

| 순서 | 액션          | 담당          | 기한   |
| ---- | ------------- | ------------- | ------ |

#### 체크포인트

- [시점 1]: [확인 사항]
- [시점 2]: [확인 사항]

---

### PD 코멘트

[종합 의견 및 방향성 제시]
```

## 리뷰 체크리스트

### 전략 관점

- [ ] 우리 게임의 핵심 가치와 부합하는가?
- [ ] 현재 가장 필요한 것인가?
- [ ] 장기 로드맵에 어떤 영향을 주는가?

### 유저 관점

- [ ] 유저가 진정으로 원하는 것인가?
- [ ] 기존 유저에게 부정적 영향은 없는가?
- [ ] 신규 유저 유입에 도움이 되는가?

### 비즈니스 관점

- [ ] 투자 대비 수익이 합리적인가?
- [ ] 수익화가 자연스러운가?
- [ ] 경쟁 우위를 확보할 수 있는가?

### 실행 관점

- [ ] 팀이 실행할 역량이 있는가?
- [ ] 일정이 현실적인가?
- [ ] 의존성/병목이 명확한가?

## 모바일 게임 PD 특화 체크

### 북미 시장 출시 검토

- [ ] 앱스토어 리뷰 리스크 검토
- [ ] 커뮤니티 반응 예측
- [ ] 인플루언서/미디어 반응 예측
- [ ] 법적 리스크 (확률 공개, 프라이버시 등)

### 중국 시장 출시 검토

- [ ] 판호 영향도 검토
- [ ] 규제 준수 여부
- [ ] 현지 경쟁 상황
- [ ] 현지 파트너 협의 필요 사항

### 라이브 서비스 검토

- [ ] 기존 유저 경험에 미치는 영향
- [ ] 롤백 가능 여부
- [ ] 모니터링 지표 정의
- [ ] 긴급 대응 계획

## 의사결정 가이드라인

### 승인 기준

- 전략적 적합성 점수 ≥ 4/5
- 치명적 리스크 없음
- 리소스 확보 가능
- 예상 ROI ≥ 기준선

### 반려 기준

- 프로젝트 비전과 불일치
- 감당 불가능한 리스크
- 리소스 대비 효과 미미
- 더 좋은 대안 존재

### 보류 기준

- 아이디어는 좋으나 타이밍 부적절
- 선행 조건 미충족
- 시장 상황 변화 관망 필요

## 후속 관리

### 승인 후 모니터링

```
[마일스톤 1] → 진행상황 체크
[마일스톤 2] → 중간 점검
[출시] → 성과 측정
[출시+2주] → 회고 및 개선
```

### 실패 시 대응

1. 원인 분석 (무엇이 잘못되었나)
2. 학습 포인트 도출
3. 롤백 또는 피봇 결정
4. 팀 공유 및 문서화

## HTML 보고서 생성

PD 리뷰 완료 후 `/report` 스킬로 HTML 보고서를 생성합니다.

### 생성 명령

```bash
# 타임스탬프 포함 파일명
[프로젝트명]_Report_YYYYMMDD-HHMMSS.html

# 예시
CRM_Analysis_Report_20260203-143052.html
```

### 보고서 포함 내용

- 핵심 요구사항
- 사용된 스킬별 분석 결과
- 종합 평가 (PD Review)
- 회의 결정 사항 / Next Steps

### 보고서 특징

- 단일 HTML 파일 (바로 공유 가능)
- 다크 모드 디자인
- 목차 네비게이션
- 반응형 레이아웃

PD 리뷰 완료 후 분석 결과를 공유해야 한다면 `/report`를 실행하세요.
