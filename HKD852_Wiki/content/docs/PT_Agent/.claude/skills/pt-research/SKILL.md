# 리서치 에이전트

프레젠테이션 품질 강화를 위해 웹 리서치를 수행하고 관련 정보를 수집합니다.

## 모델 권장사항

이 스킬은 **Sonnet** 모델을 권장합니다:

- 검색 결과 분석 및 요약 능력
- 다양한 소스에서 인사이트 도출
- 정보의 신뢰성 판단
- 비용 효율적인 처리

---

## 입력

- 스펙 문서 (pt-reception에서 생성)
- 발표 주제 및 핵심 키워드

## 1. 리서치 필요성 판단

다음 조건 중 하나라도 해당하면 **리서치 실행**:

### 필수 리서치 트리거

| 조건                  | 리서치 유형   | 예시                              |
| --------------------- | ------------- | --------------------------------- |
| 최신 통계/데이터 필요 | 데이터 리서치 | "2024년 시장 규모", "최신 트렌드" |
| 경쟁사/업계 분석 필요 | 경쟁 리서치   | "경쟁사 현황", "업계 동향"        |
| 기술/개념 설명 필요   | 개념 리서치   | "AI Agent란", "ESG 정의"          |
| 사례/레퍼런스 필요    | 사례 리서치   | "성공 사례", "벤치마크"           |
| 인용/출처 필요        | 검증 리서치   | 신뢰성 있는 데이터 확보           |

### 리서치 스킵 조건

- 내부 프로젝트 진행상황 보고
- 이미 충분한 자료가 제공됨
- 단순 안내/공지 목적
- 보안/기밀 관련 내용

---

## 2. 리서치 실행 전략

### 검색 쿼리 설계

```yaml
검색_전략:
  기본_쿼리: "[주제] + [연도]" # 예: "AI Agent 시장 2024"

  데이터_리서치:
    - "[주제] statistics [연도]"
    - "[주제] market size"
    - "[주제] growth rate"

  트렌드_리서치:
    - "[주제] trends [연도]"
    - "[주제] forecast"
    - "[주제] outlook"

  사례_리서치:
    - "[주제] case study"
    - "[주제] success story"
    - "[주제] best practices"

  개념_리서치:
    - "what is [주제]"
    - "[주제] definition"
    - "[주제] explained"
```

### 신뢰할 수 있는 출처 우선순위

1. **최우선**: 정부/공공기관, 학술 논문
2. **우선**: 유명 컨설팅 (McKinsey, BCG, Gartner)
3. **참고**: 업계 미디어, 공식 기업 블로그
4. **제외**: 개인 블로그, 위키피디아 (1차 출처 아님)

---

## 3. 검색 결과 처리

### 정보 검증 체크리스트

```
□ 출처가 신뢰할 수 있는가?
□ 발행일이 최근인가? (2년 이내 권장)
□ 데이터에 출처가 명시되어 있는가?
□ 여러 출처에서 교차 검증 가능한가?
□ 편향된 관점이 아닌가?
```

### 인사이트 추출 프레임워크

```yaml
인사이트_구조:
  핵심_발견:
    - "[가장 중요한 발견 1]"
    - "[가장 중요한 발견 2]"
    - "[가장 중요한 발견 3]"

  데이터_포인트:
    - 수치: "[구체적인 숫자]"
      출처: "[출처명]"
      연도: "[YYYY]"

  트렌드:
    - "[식별된 트렌드]"

  인용_가능:
    - 내용: "[인용문]"
      출처: "[출처]"
```

## 4. 출력: 리서치 문서

```yaml
# PT 리서치 문서
메타정보:
  리서치_일시: "[YYYY-MM-DD HH:MM]"
  리서치_유형: "[데이터|트렌드|사례|개념|복합]"
  검색_쿼리_수: N
  유효_결과_수: M

리서치_필요성:
  판단: "필요|불필요"
  근거: "[왜 리서치가 필요/불필요한지]"


# 리서치 스킵 시 여기서 종료
---
핵심_인사이트:
  요약: "[3문장 이내 핵심 요약]"

  주요_발견:
    - 발견: "[발견 내용]"
      중요도: "높음|중간|낮음"
      활용: "[어느 슬라이드에서 활용할지]"

데이터_수집:
  통계:
    - 내용: "[구체적인 통계]"
      수치: "[숫자]"
      출처: "[출처명]"
      URL: "[링크]"
      연도: "[YYYY]"
      신뢰도: "높음|중간"

  트렌드:
    - 내용: "[트렌드 설명]"
      출처: "[출처]"

인용_가능_자료:
  - 인용문: "[인용할 수 있는 문장]"
    화자: "[발언자/출처]"
    맥락: "[사용 맥락]"

시각화_제안:
  - 유형: "[차트/그래프/인포그래픽]"
    데이터: "[시각화할 데이터]"
    슬라이드: "[적용할 슬라이드 번호]"

출처_목록:
  - 제목: "[자료 제목]"
    URL: "[링크]"
    발행일: "[YYYY-MM-DD]"
    신뢰도: "높음|중간"

콘텐츠팀_권고:
  필수_반영:
    - "[반드시 포함해야 할 내용]"
  권장_반영:
    - "[포함하면 좋을 내용]"
  주의사항:
    - "[사용 시 주의할 점]"
```

## 5. 리서치 스킵 시 출력

```yaml
# PT 리서치 문서
메타정보:
  리서치_일시: "[YYYY-MM-DD HH:MM]"

리서치_필요성:
  판단: "불필요"
  근거: "[스킵 사유]"

권고:
  - "제공된 자료로 충분히 콘텐츠 설계 가능"
  - "추가 리서치 없이 진행"
```

## 파이프라인 통합

### 위치

```
[1] Reception → [1.5] Research → [2] Content → ...
    (Haiku)       (Sonnet)        (Sonnet)
       │              │
       └── 스펙 전달 ──┘
                      │
                      └── 리서치 결과 + 스펙 → Content
```

### 다음 단계

리서치 문서 생성 완료 후 스펙 문서와 함께 `/pt-content`로 전달합니다.

---

## 사용 예시

### 리서치가 필요한 경우

```
요청: "2024년 AI Agent 시장 동향에 대한 임원 보고"
→ 리서치 트리거: 최신 통계, 시장 데이터 필요
→ 검색: "AI Agent market 2024", "AI Agent trends"
→ 출력: 시장 규모, 성장률, 주요 플레이어 데이터
```

### 리서치가 불필요한 경우

```
요청: "우리 팀 3월 프로젝트 진행상황 공유"
→ 판단: 내부 자료 기반, 외부 리서치 불필요
→ 출력: 리서치 스킵 문서
```
