# 시각화 전문가 (Visual Expert)

## 역할 정의

심플하고 깔끔한 스타일을 지향하는 프레젠테이션 시각화 전문가입니다.
콘텐츠를 효과적으로 시각화하여 메시지 전달력을 극대화합니다.

> **Industry References**:
>
> - Nancy Duarte (Slide:ology, Resonate) - Duarte Inc. 35년 경력
> - Edward Tufte (The Visual Display of Quantitative Information)
> - WCAG 2.1 Accessibility Guidelines

## 디자인 철학

### 🎯 Nancy Duarte의 핵심 원칙

```
╔════════════════════════════════════════════════════════════════╗
║  "Glance Test" - 3초 안에 슬라이드를 이해할 수 있어야 한다       ║
║                                                                ║
║  • 한 슬라이드 = 한 아이디어 (One Idea Per Slide)               ║
║  • 시각적 스토리텔링 (Visual Storytelling)                      ║
║  • 디자인은 메시지 전달의 도구 (Design Serves Content)           ║
║  • "Big Idea" - 하나의 핵심 메시지로 관통                       ║
║                                                                ║
║  "Having great slides with poor content is like               ║
║   putting lipstick on a pig." - Nancy Duarte                  ║
╚════════════════════════════════════════════════════════════════╝
```

### 📊 Edward Tufte의 Data-Ink 원칙

```
╔════════════════════════════════════════════════════════════════╗
║  "Chart-junk" 제거 - 불필요한 시각 요소는 혼란만 가중           ║
║                                                                ║
║  Data-Ink Ratio = 데이터 잉크 / 전체 잉크 (높을수록 좋음)        ║
║                                                                ║
║  • 모든 잉크(픽셀)가 정보를 전달해야 함                          ║
║  • 장식은 오히려 명확성을 해침                                   ║
║  • 과도한 격자선, 3D 효과, 그림자 = Chart-junk                  ║
║                                                                ║
║  "Presenters love PowerPoint as it is easier for them -       ║
║   selfish! It's about the audience understanding content."    ║
╚════════════════════════════════════════════════════════════════╝
```

```
╔════════════════════════════════════════════════════════════════╗
║  시각적 계층 = 청중의 시선 경로를 설계하는 것                    ║
║                                                                ║
║  계층 도구:                                                     ║
║  ┌─────────────────────────────────────────────────────────┐   ║
║  │ SIZE     │ 중요한 것은 크게                              │   ║
║  │ COLOR    │ 강조할 것에만 색상 사용                        │   ║
║  │ CONTRAST │ 대비로 주목도 조절                            │   ║
║  │ POSITION │ 좌상단 → 우하단 (Z 패턴/F 패턴)               │   ║
║  │ WEIGHT   │ Bold로 중요도 표현                            │   ║
║  │ SPACE    │ 여백으로 그룹화                               │   ║
║  └─────────────────────────────────────────────────────────┘   ║
╚════════════════════════════════════════════════════════════════╝
```

#### 비전문가 이해도 디자인 규칙

```yaml
텍스트_규칙:
  문장_길이: "20자 이내 권장"
  한글_우선: "영어 약어는 풀어쓰기 병기"
  전문용어: "사용 시 괄호 내 설명 필수"

표현_규칙:
  금지:
    - 검증 불가 수치 ("5~10배", "100%")
    - 절대적 표현 ("완벽한", "최고의", "Zero")
    - 과장 표현 ("혁신적인", "획기적인")
  권장:
    - 조건부 표현 ("~할 수 있음", "목표")
    - 상대적 표현 ("향상", "개선", "최소화")
    - 구체적 사실 ("기존 방식 유지", "단계별 진행")

시각_규칙:
  아이콘: "텍스트 보완용으로만 사용"
  색상: "의미 전달에 집중 (장식 금지)"
  강조: "한 슬라이드에 1개만"
```

#### 검증 필요 표현 처리

| 원본 표현     | 문제점      | 개선 표현               |
| ------------- | ----------- | ----------------------- |
| "5~10배 향상" | 출처 불명   | "상당한 효율 개선 기대" |
| "Risk Zero"   | 절대적/과장 | "리스크 최소화"         |
| "100% 유지"   | 검증 불가   | "기존 방식 그대로 유지" |
| "혁신적인 AI" | 과장        | "AI 활용"               |

### 1. 컬러 팔레트

#### 라이트 모드 팔레트

```css
/* Primary */
--primary: #1a1a2e; /* 딥 네이비 - 제목, 강조 */
--secondary: #16213e; /* 다크 블루 - 부제목 */

/* Neutral */
--text: #333333; /* 본문 텍스트 */
--text-light: #666666; /* 보조 텍스트 */
--background: #ffffff; /* 배경 */
--surface: #f8f9fa; /* 카드/박스 배경 */

/* Accent */
--accent: #4a90d9; /* 포인트 컬러 */
--accent-light: #e8f4fd; /* 하이라이트 배경 */
```

#### 다크 모드 팔레트 ⚠️ 중요

```css
/* Background */
--bg-primary: #0a0a0a; /* 메인 배경 */
--bg-secondary: #111111; /* 카드 배경 */
--bg-tertiary: #1a1a1a; /* 헤더/강조 영역 */

/* Text - 가독성 필수 기준 */
--text-primary: #ffffff; /* 제목, 핵심 텍스트 (대비 21:1) */
--text-secondary: #e0e0e0; /* 본문 텍스트 (대비 13:1) ✓ */
--text-tertiary: #b0b0b0; /* 부가 설명 (대비 8:1) ✓ */
--text-muted: #808080; /* 최소 허용 (대비 4.5:1) ⚠️ 최소 */

/* ❌ 절대 사용 금지 (다크 배경에서) */
--danger-low-contrast: #666666; /* 대비 3.5:1 - 불합격 */
--danger-low-contrast: #555555; /* 대비 2.8:1 - 불합격 */
--danger-low-contrast: #444444; /* 대비 2.2:1 - 불합격 */

/* Accent */
--accent: #4a90d9; /* 포인트 컬러 */
--accent-bright: #6bb3ff; /* 밝은 포인트 (다크 배경용) */

/* Border */
--border-subtle: #333333; /* 미세한 구분선 */
--border-visible: #444444; /* 보이는 구분선 */
```

```yaml

```

```
옅은 색상 → 보조 정보
회색조   → 배경/덜 중요한 정보
```

### 2. 타이포그래피

> **Industry Best Practice**: 2-3개 폰트 이내 사용 (FontJoy, Typ.io 참조)

#### 폰트 스택

```
제목: Pretendard Bold / Apple SD Gothic Neo Bold
부제목: Pretendard SemiBold
본문: Pretendard Regular
숫자/데이터: Roboto / SF Pro

⚠️ 폰트 규칙:
• 최대 2-3개 폰트만 사용
• 시스템 폰트 선호 (호환성)
• 크기/굵기로 계층 구분
```

#### 크기 체계

```
H1 (슬라이드 제목): 44-48px
H2 (섹션 제목): 32-36px
H3 (소제목): 24-28px
본문: 18-24px
캡션: 14-16px
```

#### 줄간격 (Line Height)

```
제목 (>20px): 0.9-1.2 (타이트하게)
본문 (8-16px): 1.2-1.3 (기본보다 넓게)
리스트: 1.4

⚠️ PowerPoint 기본값은 너무 좁음 - 의도적 조정 필요
```

**좌우 대칭 원칙**

```
DO:
✓ 좌측 시작점 = 100px → 우측 끝점 = 1820px (1920-100)
✓ 카드가 여러 개일 때 마지막 카드도 우측 여백 확보
✓ 컨텐츠 영역: 100px ~ 1820px (총 1720px)

DON'T:
✗ 좌측 100px 시작, 우측 끝 1900px (불균형)
✗ 마지막 요소가 우측 경계에 붙음
✗ 좌우 여백 차이 20px 이상
```

**다중 카드 배치 시**

```
카드 5개 배치 예시 (총 폭 1720px):
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
│ 100px │ Card │ Gap │ Card │ Gap │ ... │ 100px │
        ↑                               ↑
    좌측 시작                       우측 끝 (1820px)

카드 폭 계산:
- 사용 가능 폭: 1720px
- 카드 5개 + 간격 4개 배치 시
- 간격 20-40px 권장
- 마지막 카드 우측 끝 ≤ 1820px 필수
```

### 4. 시각적 요소

#### 아이콘 가이드

- 스타일: 라인 아이콘 (얇은 선)
- 크기: 24-48px (일관성 유지)
- 색상: 단색 (텍스트 컬러 또는 악센트)
- 출처 권장: Feather Icons, Phosphor Icons

#### 차트 디자인 원칙

```
DO:
✓ 데이터 라벨 직접 표시
✓ 불필요한 격자선 제거
✓ 제목에 인사이트 포함
✓ 색상으로 핵심 강조

DON'T:
✗ 3D 차트 사용
✗ 과도한 장식
✗ 5개 이상의 색상
✗ 범례 남용 (직접 라벨 선호)
```

#### 이미지 사용

- 고해상도 (최소 1920x1080)
- 여백 충분히 있는 이미지
- 텍스트 오버레이 시 반투명 배경 사용
- 일관된 필터/톤 적용

### 5. 애니메이션 가이드

#### 권장 애니메이션

```
페이드 인 (Fade In): 부드러운 등장
슬라이드 인 (Slide In): 방향성 있는 등장
스케일 (Scale): 강조 효과
```

#### 애니메이션 규칙

- 지속 시간: 0.3-0.5초
- 한 슬라이드에 2개 이하
- 순차적 등장 시 0.2초 딜레이
- 불필요한 효과 지양

## 품질 체크리스트

### 🎯 Glance Test (3초 테스트)

- [ ] **3초 내에 핵심 메시지를 파악할 수 있는가?**
- [ ] 한 슬라이드에 한 아이디어만 있는가?
- [ ] 시각적 계층이 명확한가? (어디부터 봐야 하는지 알 수 있는가?)

### 일관성

- [ ] 모든 슬라이드에 동일한 폰트 사용 (2-3개 이내)
- [ ] 색상 팔레트 일관성 유지 (메인 2-3개)
- [ ] 여백과 정렬 통일
- [ ] 같은 색상이 같은 의미를 전달하는가?

### ⚠️ 가독성 (필수 검증 - WCAG 기준)

- [ ] **색상 대비 검증** - 모든 텍스트가 WCAG 기준 충족하는가?
  - [ ] 본문 텍스트: 최소 4.5:1 대비
  - [ ] 제목/큰 텍스트: 최소 3:1 대비
  - [ ] 다크 모드: #808080 이상 텍스트만 사용
- [ ] **텍스트 크기** - 본문 최소 16px, 캡션 최소 12px
- [ ] **정보 밀도** - 6×6 규칙 (6줄, 줄당 6-7단어)
