# 수치 기획 바이블 — WanChai 적용 가이드

> 袁兆阳 《游戏数值百宝书：成为优秀的数值策划》 핵심 원칙을 오토슈터 서바이버에 맞게 적용

---

## 1. 수치 설계 5단계 프로세스 (数值流程化)

모든 게임의 수치 설계는 이 5단계를 순서대로 거친다:

```
① 준비 → ② 전투 수치 → ③ 경제 수치 → ④ 복기(리뷰) → ⑤ 상업화
```

### WanChai 적용

| 단계        | 원서 내용                                       | WanChai 적용                                                                |
| ----------- | ----------------------------------------------- | --------------------------------------------------------------------------- |
| ① 준비      | 게임 유형·장르·3차원 분석, 목표 게임 설정       | 세로 오토슈터 서바이버 분석, Vampire Survivors / BangBang Survivor 벤치마크 |
| ② 전투 수치 | 속성 정의 → 전투 프레임워크 → 능력 량화 → AI    | 무기 DPS → 적 HP/속도 → 웨이브 스케일링 → 적 AI 행동 패턴                   |
| ③ 경제 수치 | 경제 모델 → 매개체 → I/O 프레임워크 → 가치 체계 | 킬=XP/골드 투입, 레벨업=무기/패시브 산출, 메타 강화=영구 보상               |
| ④ 복기      | 경제·양성·전투 복기                             | 스테이지별 클리어율, DPS 대 적 HP 비율, 생존 시간 분포                      |
| ⑤ 상업화    | 과금 설계, 운영 전략                            | Phase 2 이후 (현재 해당 없음)                                               |

## 2. 속성 계층 체계 (属性分级)

### 원칙: 3단계 속성 분류

| 계층         | 정의                                 | 특성                 |
| ------------ | ------------------------------------ | -------------------- |
| **1차 속성** | 전투에 직접 참여하는 기초 속성       | 확정적, 매 전투 사용 |
| **2차 속성** | 1차 속성 위에 구축, 단일 피해에 영향 | 확률적 (%), 랜덤성   |
| **3차 속성** | 1·2차 속성을 보정                    | 후기 밸런스 조정용   |

### WanChai 매핑

| 계층    | 속성                    | 설명                                     |
| ------- | ----------------------- | ---------------------------------------- |
| **1차** | baseDamage              | 무기 기본 공격력, 직접 DPS에 영향        |
| **1차** | cooldownMs              | 무기 발사 간격, DPS의 분모               |
| **1차** | baseHp (적)             | 적 내구도 — 처치에 필요한 총 데미지 결정 |
| **1차** | baseSpeed (적)          | 적 이동 속도 — 기지에 도달하는 시간 결정 |
| **2차** | critChance / critDamage | 확률적 추가 피해 (기본 2.0x)             |
| **2차** | piercing                | 관통 수 — 한 발로 여러 적 처리           |
| **3차** | damageMultiplier        | 메타 강화/레벨업 패시브 보정값           |
| **3차** | attackSpeedMultiplier   | 메타 강화/레벨업 패시브 보정값           |

### 패널 속성 공식

> **실제값 = 기초값 × 레벨배율 × 플레이어배율**

```
실제 데미지 = baseDamage × levelMult(1 + (level-1)×0.2) × damageMultiplier
실제 쿨다운 = cooldownMs / attackSpeedMultiplier
DPS = 실제 데미지 × projectileCount / (실제 쿨다운 / 1000)
```

## 3. 전투 프레임워크 (战斗框架)

### 감산 공식 vs 승산 공식

| 공식 유형       | 형태                        | 장점          | 단점                   |
| --------------- | --------------------------- | ------------- | ---------------------- |
| **감산 (减法)** | Damage = ATK - DEF          | 직관적        | 방어 스택 시 무적 가능 |
| **승산 (乘法)** | Damage = ATK × (1 - 경감률) | 밸런스 안정적 | 계산 복잡              |
| **혼합**        | ATK² / (ATK + DEF)          | 유연함        | 직관성 떨어짐          |

### WanChai 전투 공식

현재 WanChai는 **승산형 데미지 모델**:

```
최종 데미지 = baseDamage × levelMult × damageMultiplier × (isCrit ? critDamage : 1.0)
적 체력 = baseHp × stageHpMult × (isElite ? 3.0 : 1.0)
```

**데미지 계산 흐름**:

1. 무기 baseDamage에 레벨 배율 적용 (레벨당 +20%)
2. 플레이어 damageMultiplier 적용 (패시브/메타 강화)
3. 크리티컬 판정 (critChance 확률로 critDamage 배율 적용)
4. 적 HP에서 최종 데미지 감산
5. 기지 아머 보정: 적 공격 → baseDamage × (1 - armorPercent) → 기지 HP 감소

## 4. 능력 량화 — 전투력 (能力量化/战斗力)

### 원칙

> 전투력(CP) = EHP × APS (유효 체력 × 초당 공격력)
> — 승산형이 가산형보다 정확하고 직관적

### WanChai 적용: DPS 대 적 HP 비율

```
총 DPS = Σ(무기별 DPS)
적 초당 유입 HP = 스폰 수/초 × 평균 적 HP
```

| 지표                   | 계산                     | 의미                                       |
| ---------------------- | ------------------------ | ------------------------------------------ |
| **DPS 효율**           | 총 DPS / 적 초당 유입 HP | > 1.0 = 적 처리 가능, < 1.0 = 밀림         |
| **기지 생존 시간**     | 기지 HP / (누수 DPS)     | 적이 돌파했을 때 버틸 수 있는 시간         |
| **TTK (Time-to-Kill)** | 적 HP / 총 DPS           | 단일 적 처치 소요 시간                     |
| **무기 커버리지**      | 무기 사거리 / 화면 폭    | 1.0 = 전 영역 커버, 부족하면 빈 구간 발생  |
| **여유도**             | DPS 효율 / 1.0           | > 1.5 = 여유, 1.0~1.5 = 적정, < 1.0 = 위험 |

## 5. 경제 수치 — I/O 구조 (经济数值)

### 원칙: 투입-산출 프레임워크

```
투입(Input) → [게임 시스템] → 산출(Output)
```

### WanChai I/O 매핑

```
투입(Input):                     산출(Output):
├─ 생존 시간                      ├─ XP (킬 → 레벨업)
├─ 적 처치 수                     ├─ 골드 (킬당 1, 엘리트 5, 보스 50)
├─ 무기 선택 전략                 ├─ 레벨업 선택지 (무기/패시브)
└─ 레벨업 의사결정                └─ 메타 강화 (영구 stats)
```

### 소비 모델 (消耗模型)

> 초반 소액 소비 → 고빈도 피드백 → 후반 대량 소비 → 깊이 보장

WanChai 적용 (6스테이지 구조):

- **스테이지 1 (중환 구역)**: 적 3종 (basic, fast, swarm) → 빠른 레벨업 → 무기 획득 경험
- **스테이지 2 (중환 보스)**: 첫 보스 (HP 1200) → 보스전 경험 학습
- **스테이지 3~4 (침사추이)**: 적 6종 + 원거리 적 등장 → 전략적 무기 선택 요구
- **스테이지 5~6 (빅토리아 피크)**: 전 적 종류 + 최종 보스 (HP 3000) → 풀 빌드 필요

### 가치 체계 (价值体系)

```
기본 적 1킬 = XP 1 + 골드 1
엘리트 1킬 = XP × 3 + 골드 5
보스 1킬 = XP 100 + 골드 50
레벨업 1회 = 무기 획득/강화 또는 패시브 1단계
```

**성가비(性价比) 원칙**: 무기 간 DPS/쿨다운 비율이 균등해야 함

```
무기별 DPS = baseDamage × projectileCount / (cooldownMs / 1000)
에너지 샷: 10 × 1 / 0.8 = 12.5 DPS
산탄총:    10 × 5 / 1.2 = 41.7 DPS (근거리 제한)
레이저 빔: 25 × 1 / 2.0 = 12.5 DPS (관통 보너스)
```

## 6. 성장 곡선 (养成曲线/成长函数)

### 곡선 유형

| 유형          | 함수           | 용도                            |
| ------------- | -------------- | ------------------------------- |
| **선형**      | y = ax + b     | 초반 난이도 증가                |
| **가속 성장** | y = ax^n (n>1) | 후반 급격한 난이도              |
| **감속 성장** | y = ax^n (n<1) | 초반 빠른 성장, 후반 안정       |
| **S자 곡선**  | 시그모이드     | 초반 완만→중반 급성장→후반 안정 |

### WanChai 난이도 곡선 설계

```
스테이지 내 난이도 = f(경과 시간)
스테이지 간 난이도 = f(스테이지 번호)
```

**스테이지 내 (60초 웨이브)**:

- 스폰 간격: 800ms × 0.45^(분) → 60초 후 약 400ms (최소)
- 스폰 수: 1 + floor(분 × 3) → 60초 후 약 4마리/웨이브
- 엘리트 확률: 10% + 25%/분 → 60초 후 35% (최대 50%)

**스테이지 간 (누적 스케일링)**:

- 적 HP: ×1.5/스테이지
- 적 속도: ×1.15/스테이지
- 적 공격력: ×1.25/스테이지

**난이도 증가 수단**:

- 스폰 간격 감소 → 화면 내 적 수 증가 → DPS 압박
- 적 종류 해금 → zigzag, teleport 등 회피형 적 등장
- 엘리트 비율 증가 → HP 3배 적 빈도 증가
- 보스 HP 증가 → 스테이지별 1200 → 1800 → 3000

## 7. 수치 복기 (数值复盘)

### 3차원 복기

| 차원          | 점검 항목                | WanChai 적용                                                  |
| ------------- | ------------------------ | ------------------------------------------------------------- |
| **전투 복기** | 공식 밸런스, 전투력 분포 | 무기별 DPS, TTK, 적 HP 스케일링                               |
| **경제 복기** | I/O 균형, 인플레이션     | XP 획득 속도 vs 레벨업 비용 곡선, 골드 수입 vs 메타 강화 비용 |
| **양성 복기** | 성장 곡선, 정체 구간     | 레벨업 빈도, 무기 강화 체감                                   |

### 검증 방법

| 방법                        | 설명                    | WanChai 적용                          |
| --------------------------- | ----------------------- | ------------------------------------- |
| **스프레드시트 시뮬레이션** | 엑셀/시트로 수치 모델링 | DPS vs 적 HP 유입량 시뮬레이션        |
| **자동 시뮬레이션**         | 코드 기반 반복 테스트   | Vitest로 WaveDirector/DamageCalc 검증 |
| **실제 플레이테스트**       | 실제 게임 내 테스트     | 브라우저에서 플레이                   |

### 핵심 KPI

```
1. 스테이지 클리어율 = 클리어 수 / 총 시도 (이상: S1 90%, S3 60%, S5 30%)
2. 평균 생존 시간 = Σ생존시간 / 시도 수 (이상: S1 55s+, S3 40s+)
3. DPS 효율 = 총 DPS / 적 초당 유입 HP (적정: 1.2~2.0)
4. 레벨업 빈도 = 레벨업 횟수 / 생존 시간(분) (적정: 3~5회/분)
```

## 8. 밸런스 설계 원칙 (平衡性)

### 핵심 원칙

1. **대항 속성 최대화**: 가능한 모든 속성을 대항 쌍으로 설계
   - WanChai: 무기 DPS ↔ 적 HP, 플레이어 이동속도 ↔ 적 속도, 관통 ↔ 적 밀집도

2. **비율 상한 설정**: 퍼센트 증가에 상한선을 두어 후반 밸런스 붕괴 방지
   - WanChai: 엘리트 확률 최대 50%, 적 속도 배율 최대 2.8x, 무기 최대 4종

3. **분배율로 관리**: 소프트캡 대신 획득 분배율로 밸런스 조절
   - WanChai: 레벨업 시 무기 3종 + 패시브 중 선택 → 선택지 분배로 파워 커브 조절

4. **플레이어 경험 우선**: 수치가 아닌 플레이어가 체감하는 결과를 설계
   - WanChai: "이 무기가 얼마나 많은 적을 쓸어주는가"가 직관적이어야 함

5. **성가비 균등**: 같은 투자 대비 같은 수준의 보상
   - WanChai: 모든 무기의 레벨당 DPS 증가율이 비슷해야 함 (레벨당 +20% 공통)

## 9. 확률 메카닉 (概率机制)

### 극단적 부정 결과 방지

| 방법                 | 설명                           | WanChai 적용                                        |
| -------------------- | ------------------------------ | --------------------------------------------------- |
| **점진적 확률 증가** | 실패할수록 다음 성공 확률 증가 | 레벨업 선택지에서 미보유 무기 우선 등장             |
| **빈도 변환**        | 확률 → 확정적 빈도로 변환      | 보스 스폰은 확률이 아닌 시간 기반 (bossTimeMinutes) |

### 판정 방법

| 방법                        | 원리                           | 적합한 경우                 |
| --------------------------- | ------------------------------ | --------------------------- |
| **순차 판정** (Sequential)  | 우선순위 높은 것부터 순차 판정 | 크리티컬 → 일반 데미지 순서 |
| **원탁 판정** (Round-table) | 전체 확률 풀에서 균등 배분     | 레벨업 선택지 풀            |

## 10. 수치 모듈화 & 시각화

### 모듈화 원칙

- 변경 가능한 파라미터를 한 곳에 집중 → `src/config/balance.ts`
- 무기 정의는 `src/config/weapons.ts`, 적 정의는 `src/config/enemies.ts`에 분리
- 스케일링 파라미터로 전체 크기를 즉시 조절
- 데이터 유효성 검사로 오입력 방지

### 시각화 원칙

- **리듬감**: 웨이브 스테이지 (긴장) → 보스 (절정) → 스테이지 클리어 (이완) 교차
- **의식감**: 레벨업 선택 시 일시 정지 → 의미 있는 결정의 무게감
- **몰입 (Flow)**: 적 밀도가 점진적으로 증가하여 플레이어 성장과 맞물려야 함
