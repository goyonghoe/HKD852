## 2. 특수 적 타입

일반 적에 **추가 특성(modifier)**을 부여하여 특수 적을 생성한다. 모든 티어에 적용 가능.

### 2.1 특수 타입 목록

| 타입       | 영문        | 시각 표시                 | 효과                                   | 대항 메카닉 (크리터)                    |
| ---------- | ----------- | ------------------------- | -------------------------------------- | --------------------------------------- |
| **아머**   | Armored     | 은색 테두리 + 방패 아이콘 | 첫 히트 무효 (이후 정상 피해)          | 연타(Double Strike) — 2히트로 아머 관통 |
| **분열**   | Splitting   | 균열 패턴 + 작은 얼굴 2개 | 죽으면 같은 원소 T1 2마리 생성         | 스플래시(Splash) — 분열체 즉시 처리     |
| **흡수**   | Absorbing   | 맥동 아우라 + 연결선      | 인접 동일 원소 적의 HP 회복 (턴당 1)   | 저주(Curse) — HP-1로 흡수 상쇄          |
| **역병핵** | Blight Core | 보라 맥동 + 눈 다수       | 주변 3x3 모든 적 턴당 HP+1 (보스 전용) | 관통(Pierce) — 핵 직접 타격             |

### 2.2 특수 타입 세부 규칙

#### 아머 (Armored)

```
피해 계산:
  첫 히트: damage = 0 (아머 파괴, 시각적 은색 테두리 소멸)
  이후 히트: damage = normal (AP 1 → HP 1)

카운터:
  - 연타(Double Strike) 패시브: 1AP에 2히트 → 아머 파괴 + 1데미지 동시
  - 일반 크리터: 아머 파괴에 AP 1 소비 → 실질 AP 효율 저하
```

> 패널 공식: `필요 AP = HP + 아머 수(1) = HP + 1`

#### 분열 (Splitting)

```
사망 시:
  - 원래 위치 + 인접 빈 칸에 T1 2마리 생성
  - 인접 빈 칸이 없으면 1마리만 생성
  - 생성된 T1도 보드에 추가 (추가 처치 필요)

카운터:
  - 스플래시(Splash) 패시브: 원본 처치 시 인접 1딜 → 분열체 즉시 HP-1
  - 분열체는 아머/분열 특성 미보유 (순수 T1)
```

> 패널 공식: `실질 HP = 원본 HP + (분열체 수 x T1 HP) = HP + 2`

#### 흡수 (Absorbing)

```
턴 시작 시:
  - 인접(상하좌우) 동일 원소 적이 있으면 그 적 HP+1 (최대 원본 HP까지)
  - 자기 자신의 HP는 변화 없음
  - 흡수는 크리터 출격 전 적용

카운터:
  - 저주(Curse) 패시브: 전투 시작 시 같은 원소 적 HP-1 → 흡수 회복 상쇄
  - 흡수 적을 우선 제거하면 인접 적의 HP 회복 차단
```

> 수치 바이블 Section 9: 흡수는 **턴당 HP+1, 최대치 = 원본 HP**로 무한 회복 방지

#### 역병핵 (Blight Core) — 보스 전용

```
매 턴 시작 시:
  - 자신 중심 3x3 범위 모든 적 HP+1
  - 자기 자신도 HP+1
  - 상한: 없음 (보스 페이즈이므로 시간 제한이 긴장감)

카운터:
  - 관통(Pierce) 패시브: LoS 무시하여 핵 직접 타격
  - 핵 파괴 시 주변 강화 즉시 중단
  - 핵의 기본 HP는 5 (보스 최우선 처리 대상)
```

### 2.3 특수 적 출현 규칙

| Floor   | 아머 출현율 | 분열 출현율 | 흡수 출현율 | 역병핵       |
| ------- | ----------- | ----------- | ----------- | ------------ |
| Floor 1 | 0~10%       | 0%          | 0%          | 없음         |
| Floor 2 | 10~20%      | 5~10%       | 0%          | 없음         |
| Floor 3 | 15~25%      | 10~15%      | 5~10%       | 없음         |
| Boss    | 20~30%      | 10~20%      | 10~15%      | **1개 고정** |
| 엘리트  | +10% 가산   | +5% 가산    | +5% 가산    | 없음         |

### 3.2 보스 전투 구조

```
보스 보드 레이아웃 (예: W1 화염드레이크):

  [T1] [T1] [T2] [T1] [T1]
  [T1] [  핵  ] [  보스  ] [T1]     ← 역병핵 + 보스 2x2 또는 1x1
  [T2] [T1] [T1] [T1] [T2]
  [T1] [T1] [T2] [T1] [T1]

보스 = 보드의 중앙 영역 차지 (2x2 타일 또는 1x1 강화)
역병핵 = 보스 인접 배치
```

### 3.3 보스 페이즈

| 페이즈  | 조건           | 변화                                        |
| ------- | -------------- | ------------------------------------------- |
| Phase 1 | 보스 HP > 50%  | 기본 능력 + 역병핵 강화                     |
| Phase 2 | 보스 HP <= 50% | 특수 능력 활성화 + 추가 적 소환             |
| Phase 3 | 보스 HP <= 25% | 연출 강화 (시각 이펙트), 역병핵 HP 회복 1회 |

## 4. 적 데이터 구조

### 4.1 기존 Cube 확장

```typescript
// 기존 Cube 인터페이스에 적 정보 추가
interface BlightData {
  blightId: string; // "fire_t1_ember_slime"
  tier: 1 | 2 | 3;
  modifier?: 'armored' | 'splitting' | 'absorbing' | 'blight_core';
  isBoss?: boolean;
  bossPhase?: number;
  displayName: string; // UI 표시용
}

// 기존 Cube와의 관계
interface Cube {
  // ... 기존 필드 유지
  element: ElementColor;
  hp: number;
  // 신규
  blight?: BlightData; // 없으면 기존 컬러 큐브로 동작 (하위 호환)
}
```

### 4.2 하위 호환

- `blight` 필드가 없는 Cube는 기존 방식대로 동작
- 기존 World 1 레벨 데이터는 수정 없이 사용 가능
- 로그라이크 모드에서만 `blight` 데이터 활성화

## 5. 시각 디자인 원칙

### 5.1 적 스프라이트 규격

| 속성       | T1            | T2           | T3 / 보스           |
| ---------- | ------------- | ------------ | ------------------- |
| 기본 크기  | 48x48         | 64x64        | 80x80               |
| Cube 매핑  | CubeSize S    | CubeSize M   | CubeSize L          |
| 애니메이션 | idle 2프레임  | idle 3프레임 | idle 4프레임        |
| 역병 표시  | 보라 점 1~2개 | 보라 아우라  | 보라 맥동 + 눈 발광 |

### 5.2 컬러 규칙

- 적 주색 = 원소 shadow 컬러 (어두운 버전)
- 역병 표시 = Dark shadow (`#6c3483`) 아우라/점
- 특수 타입 표시:
  - 아머: 은색(`#c0c0c0`) 테두리 4px
  - 분열: 균열선 2개 (base 컬러)
  - 흡수: 맥동 아우라 (원소 highlight, alpha pulse 0.2~0.6)
  - 역병핵: 보라 맥동 + 눈 3개 이상

### 5.3 프로시저럴 생성

기존 art-style-guide.md의 프로시저럴 원칙을 따른다:

- TextureFactory에서 Graphics API로 생성
- 티어별 실루엣 패턴으로 구분
- 런타임 생성 후 캐싱

## 6. 속성 계층 분석 (수치 바이블 Section 2)

### 6.1 적 속성 계층

| 계층    | 속성                 | 설명                      |
| ------- | -------------------- | ------------------------- |
| **1차** | HP                   | 내구도, 매 전투 직접 참여 |
| **1차** | Element              | 매칭 대상 결정            |
| **2차** | Modifier (특수 타입) | 조건부 방어 메카닉        |
| **2차** | 티어                 | HP 결정 + 시각 차별화     |
| **3차** | 보스 페이즈          | 전투 중 난이도 단계 변화  |
| **3차** | 출현율               | Floor/World별 분포 조절   |

### 6.2 대항 속성 쌍

| 적 속성               | 크리터 대항         | 균형 목표                    |
| --------------------- | ------------------- | ---------------------------- |
| HP (1~3)              | AP (2~9)            | AP 1 = HP 1 소거             |
| 아머 (+1 실질 HP)     | 연타 (2히트/AP)     | 연타 1회 = 아머 무효화       |
| 분열 (+2 실질 HP)     | 스플래시 (인접 1딜) | 스플래시 = 분열체 1~2 즉처리 |
| 흡수 (턴당 HP+1)      | 저주 (HP-1 선제)    | 저주 = 흡수 1턴 상쇄         |
| 역병핵 (범위 HP+1/턴) | 관통 (LoS 무시)     | 관통 = 핵 우선 타격 가능     |

### 7.2 배치 예시 (Floor 1 전투)

```
4x4 보드, 원소 2종 (Fire + Water):

  [F_T1] [W_T1] [F_T1] [W_T1]
  [W_T1] [F_T2] [W_T1] [F_T1]
  [F_T1] [W_T1] [F_T1] [W_T2]
  [W_T1] [F_T1] [W_T1] [F_T1]

총 HP: T1x12(=12) + T2x2(=4) = 16
원소: Fire 8, Water 8
필요 AP: 16 (이론) / 실제: ~22 (여유도 계수 1.3~1.4)
```

### 7.3 배치 예시 (Boss)

```
5x6 보드, 원소 5종 + 역병핵:

  [F_T2_A] [W_T1] [E_T2] [Wi_T1] [L_T1]
  [D_T1]   [ 핵 ] [F_T3] [W_T2]  [E_T1]
  [Wi_T2]  [L_T2] [보스 ] [D_T2]  [F_T1]
  [E_T1]   [W_T1] [Wi_T1] [L_T1_S] [D_T1]
  [F_T1]   [D_T1] [E_T2] [W_T1]  [Wi_T1]
  [L_T1]   [F_T1] [W_T2] [D_T1]  [E_T1]

총 HP: ~45 (핵 5 + 보스 5~10 + 잡몹 30)
```
