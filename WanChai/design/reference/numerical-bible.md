# 수치 기획 바이블 — WanChai 적용 가이드

> 袁兆阳 《游戏数值百宝书：成为优秀的数值策划》 핵심 원칙을 퍼즐 게임에 맞게 적용

---

## 1. 수치 설계 5단계 프로세스 (数值流程化)

모든 게임의 수치 설계는 이 5단계를 순서대로 거친다:

```
① 준비 → ② 전투 수치 → ③ 경제 수치 → ④ 복기(리뷰) → ⑤ 상업화
```

### WanChai 적용

| 단계 | 원서 내용 | WanChai 적용 |
|------|----------|-------------|
| ① 준비 | 게임 유형·장르·3차원 분석, 목표 게임 설정 | 퍼즐 장르 분석, Pixel Flow 벤치마크 |
| ② 전투 수치 | 속성 정의 → 전투 프레임워크 → 능력 량화 → AI | 원소 속성 → 파괴 공식 → AP/큐브HP 밸런스 → 벨트 AI |
| ③ 경제 수치 | 경제 모델 → 매개체 → I/O 프레임워크 → 가치 체계 | 히어로 큐=투입, 큐브 파괴=산출, 스코어=보상 |
| ④ 복기 | 경제·양성·전투 복기 | 레벨별 클리어율 분석, 스코어 분포, 스타 달성률 |
| ⑤ 상업화 | 과금 설계, 운영 전략 | Phase 2 이후 (현재 해당 없음) |

## 2. 속성 계층 체계 (属性分级)

### 원칙: 3단계 속성 분류

| 계층 | 정의 | 특성 |
|------|------|------|
| **1차 속성** | 전투에 직접 참여하는 기초 속성 | 확정적, 매 전투 사용 |
| **2차 속성** | 1차 속성 위에 구축, 단일 피해에 영향 | 확률적 (%), 랜덤성 |
| **3차 속성** | 1·2차 속성을 보정 | 후기 밸런스 조정용 |

### WanChai 매핑

| 계층 | 속성 | 설명 |
|------|------|------|
| **1차** | AP (Attack Power) | 히어로가 발사할 수 있는 횟수, 직접 전투 참여 |
| **1차** | Element (원소) | 매칭 대상 결정 (Fire/Water/Earth/Wind/Light/Dark) |
| **1차** | Cube HP | 큐브 내구도 (기본 1, 강화 큐브 2~3) |
| **2차** | 슬링 콤보 배율 | 빠른 연속 배치 시 스코어 보너스 (+10%/콤보, 최대 +50%) |
| **2차** | 벨트 포지션 효율 | 어떤 엣지에서 발사하느냐에 따른 적중 확률 차이 |
| **3차** | 별 기준 점수 | 최종 보정, 난이도 체감 조절 |
| **3차** | 보너스 스코어 | 잔여 히어로 보너스 (200점/히어로) |

### 패널 속성 공식

> **실제값 = 기초값 × 계수 + 보정값**

```
실제 파괴 스코어 = 기본 큐브 점수(100) × 슬링 배율(1 + combo×0.1) + 보너스(0)
```

## 3. 전투 프레임워크 (战斗框架)

### 감산 공식 vs 승산 공식

| 공식 유형 | 형태 | 장점 | 단점 |
|----------|------|------|------|
| **감산 (减法)** | Damage = ATK - DEF | 직관적 | 방어 스택 시 무적 가능 |
| **승산 (乘法)** | Damage = ATK × (1 - 경감률) | 밸런스 안정적 | 계산 복잡 |
| **혼합** | ATK² / (ATK + DEF) | 유연함 | 직관성 떨어짐 |

### WanChai 전투 공식

현재 WanChai는 **단순 매칭 파괴** 모델:
```
히어로 원소 == 큐브 원소 → AP 1 소모 → 큐브 HP 1 감소
큐브 HP ≤ 0 → 파괴 → Score += 100 × sling_multiplier
```

**향후 확장 시 고려할 공식 체계**:
- 원소 상성 (승산 공식): 유리 속성 = ×1.5 피해, 불리 속성 = ×0.5 피해
- 히어로 스킬: 폭탄(범위 파괴), 관통(일렬 파괴), 속성 변환
- 강화 큐브: HP > 1인 큐브에 대한 다중 타격 필요

## 4. 능력 량화 — 전투력 (能力量化/战斗力)

### 원칙

> 전투력(CP) = EHP × APS (유효 체력 × 초당 공격력)
> — 승산형이 가산형보다 정확하고 직관적

### WanChai 적용: 레벨 난이도 지표

```
레벨 난이도 = 총 큐브 수 × 평균 큐브 HP / 총 가용 AP
```

| 지표 | 계산 | 의미 |
|------|------|------|
| **AP 효율** | 총 AP / 총 큐브 HP | > 1.0 = AP 여유, < 1.0 = AP 부족 (불가능) |
| **원소 커버리지** | 히어로 원소 종류 / 큐브 원소 종류 | 1.0 = 완전 커버 |
| **이론 최저 AP** | 총 큐브 HP | 모든 발사가 적중할 때 필요한 최소 AP |
| **실제 필요 AP** | 이론 최저 × 1.3~1.8 | 벨트 순환으로 인한 빗나감 고려 |
| **여유도** | 총 AP / 실제 필요 AP | easy: 1.5+, normal: 1.2~1.5, hard: 1.0~1.2 |

## 5. 경제 수치 — I/O 구조 (经济数值)

### 원칙: 투입-산출 프레임워크

```
투입(Input) → [게임 시스템] → 산출(Output)
```

### WanChai I/O 매핑

```
투입(Input):                     산출(Output):
├─ 히어로 큐 (AP 총합)          ├─ 파괴된 큐브 수
├─ 히어로 원소 분포              ├─ 스코어
├─ 플레이어 전략 (배치 순서)     ├─ 별 등급 (1~3)
└─ 슬링 타이밍                   └─ 클리어/게임오버
```

### 소비 모델 (消耗模型)

> 초반 소액 소비 → 고빈도 피드백 → 후반 대량 소비 → 깊이 보장

WanChai 적용:
- **스테이지 1~3**: AP 여유 (easy) → 성공 경험 쌓기
- **스테이지 4~6**: AP 적정 (normal) → 전략적 배치 요구
- **스테이지 7+**: AP 타이트 (hard) → 최적화 필요

### 가치 체계 (价值体系)

```
큐브 1개의 기본 가치 = 100점
슬링 콤보 1단계 추가 가치 = +10점 (10%)
잔여 히어로 1명 = 200점 (클리어 보너스)
```

**성가비(性价比) 원칙**: 모든 히어로의 AP당 가치가 균등해야 함
```
AP당 기대 스코어 = Σ(파괴 가능 큐브 × 100) / 총 AP
```

## 6. 성장 곡선 (养成曲线/成长函数)

### 곡선 유형

| 유형 | 함수 | 용도 |
|------|------|------|
| **선형** | y = ax + b | 초반 난이도 증가 |
| **가속 성장** | y = ax^n (n>1) | 후반 급격한 난이도 |
| **감속 성장** | y = ax^n (n<1) | 초반 빠른 성장, 후반 안정 |
| **S자 곡선** | 시그모이드 | 초반 완만→중반 급성장→후반 안정 |

### WanChai 난이도 곡선 설계

```
스테이지 난이도 = f(스테이지 번호)

권장: S자 곡선
  - 1~3: 완만한 증가 (튜토리얼)
  - 4~7: 급격한 난이도 상승 (코어 챌린지)
  - 8~10: 안정 (마스터 영역)
```

**난이도 증가 수단**:
- 큐브 행/열 수 증가 → 벨트 포지션 증가 → AP 낭비 증가
- 원소 종류 증가 → 매칭 확률 감소
- 강화 큐브 (HP > 1) 배치
- 히어로 AP 감소 → 효율적 배치 강제
- 벨트 슬롯/벤치 슬롯 감소 → 오버플로우 위험 증가

## 7. 수치 복기 (数值复盘)

### 3차원 복기

| 차원 | 점검 항목 | WanChai 적용 |
|------|----------|-------------|
| **전투 복기** | 공식 밸런스, 전투력 분포 | 레벨별 AP 효율, 원소 커버리지 |
| **경제 복기** | I/O 균형, 인플레이션 | 스코어 분포, 별 달성률 |
| **양성 복기** | 성장 곡선, 정체 구간 | 난이도 곡선 자연스러움 |

### 검증 방법

| 방법 | 설명 | WanChai 적용 |
|------|------|-------------|
| **스프레드시트 시뮬레이션** | 엑셀/시트로 수치 모델링 | AP-큐브 매칭 시뮬레이션 |
| **자동 시뮬레이션** | 코드 기반 반복 테스트 | Vitest로 deterministic 오비트 검증 |
| **실제 플레이테스트** | 실제 게임 내 테스트 | 브라우저에서 플레이 |

### 핵심 KPI

```
1. 클리어율 = 클리어 횟수 / 총 시도 (이상: easy 90%, normal 60%, hard 30%)
2. 평균 별 = Σ별 / 시도 수 (이상: easy 2.5+, normal 1.5+, hard 1.0+)
3. AP 사용률 = 사용된 AP / 총 가용 AP (이상: 60~90%)
4. 빈 발사율 = 매칭 실패 발사 / 총 발사 (적정: 20~40%)
```

## 8. 밸런스 설계 원칙 (平衡性)

### 핵심 원칙

1. **대항 속성 최대화**: 가능한 모든 속성을 대항 쌍으로 설계
   - WanChai: 히어로 AP ↔ 큐브 HP, 원소 매칭 ↔ 원소 다양성

2. **비율 상한 설정**: 퍼센트 증가에 상한선을 두어 후반 밸런스 붕괴 방지
   - WanChai: 슬링 콤보 최대 5 (50% 보너스 상한)

3. **분배율로 관리**: 소프트캡 대신 획득 분배율로 밸런스 조절
   - WanChai: AP 배분으로 난이도 조절 (높은 AP = 쉬움, 낮은 AP = 어려움)

4. **플레이어 경험 우선**: 수치가 아닌 플레이어가 체감하는 결과를 설계
   - WanChai: "이 히어로로 뭘 할 수 있는가"가 직관적이어야 함

5. **성가비 균등**: 같은 투자 대비 같은 수준의 보상
   - WanChai: 모든 원소의 AP당 기대 파괴 수가 비슷해야 함

## 9. 확률 메카닉 (概率机制)

### 극단적 부정 결과 방지

| 방법 | 설명 | WanChai 적용 |
|------|------|-------------|
| **점진적 확률 증가** | 실패할수록 다음 성공 확률 증가 | 향후 가챠/스킬 시스템에 적용 |
| **빈도 변환** | 확률 → 확정적 빈도로 변환 | 슬링 브레이크 쿨다운 (확률 아닌 확정) |

### 판정 방법

| 방법 | 원리 | 적합한 경우 |
|------|------|-----------|
| **순차 판정** (Sequential) | 우선순위 높은 것부터 순차 판정 | 히트/크리티컬/블록 순서 |
| **원탁 판정** (Round-table) | 전체 확률 풀에서 균등 배분 | 드롭 테이블 |

## 10. 수치 모듈화 & 시각화

### 모듈화 원칙
- 변경 가능한 파라미터를 한 곳에 집중 → `src/config/balance.ts`
- 스케일링 파라미터로 전체 크기를 즉시 조절
- 데이터 유효성 검사로 오입력 방지

### 시각화 원칙
- **리듬감**: 쉬운 구간과 어려운 구간의 교차
- **의식감**: 클리어/별 달성 시 시각적 보상
- **몰입 (Flow)**: 난이도가 플레이어 실력과 맞물려야 함
