## A. 스테이지별 적 HP/ATK/SPD 스케일링

### 스케일링 공식

- **스테이지 배율**: `pow(mult, stage - 1)` (누적)
  - HP: ×1.5/stage, SPD: ×1.15/stage, ATK: ×1.25/stage
- **시간 배율** (웨이브 스테이지 내): `pow(scalePerMin, minutes)`
  - HP: 2.2x/min, SPD: 1.5x/min (cap 2.8x), ATK: 2.0x/min
- **엘리트 배율**: HP ×3, ATK ×2, XP ×5

### Lv5 무기 4슬롯 합산 DPS 추정

플레이어가 4개 무기 슬롯을 보유 (`maxWeapons: 4`). 최적 빌드 가정:

| 빌드      | 무기 조합                              | 합산 DPS (Lv5)                      | 패시브 포함 예상 |
| --------- | -------------------------------------- | ----------------------------------- | ---------------- |
| 올라운드  | shotgun + lightning + laser + missile  | 45 + 61.7 + 36 + 32.3 = **175.0**   | ~245 (dmg +40%)  |
| AoE 특화  | lightning + bomb + napalm + shotgun    | 61.7 + 33.4 + 92.8 + 45 = **232.9** | ~326 (dmg +40%)  |
| 관통 특화 | laser + railgun + shuriken + lightning | 36 + 32 + 36 + 61.7 = **165.7**     | ~232             |

패시브 `damage` Lv5 = +75%, `attack_speed` Lv5 = +50%, `crit_chance` Lv5 = 25%

**풀 빌드 DPS 추정** (dmg +75%, atkSpd +50%, crit 25% × 2.0):

- 올라운드: 175 × 1.75 × 1.5 × 1.25 = **~574 DPS**
- AoE: 232.9 × 1.75 × 1.5 × 1.25 = **~764 DPS**

### 분당 HP 스케일링 vs 플레이어 DPS 성장

### 45마리 상한선 도달 시점

- **스폰율**: S1 기준 t=0에서 1.25마리/s → t=60에서 11.08마리/s
- **적 체류 시간**: 화면 횡단 ~15초 (speed 45, 거리 ~700px)
- **예상 도달 시점**: t=30~40초 (적 처리 속도에 의존)

**판정: PASS** -- 캡이 45마리로 설정되어 프레임 드롭 방지. 적절한 압박감.

### 엘리트 50% 도달 시점

`eliteChanceBase(0.1) + eliteChancePerMin(0.25) × minutes = 0.5`
→ `minutes = (0.5 - 0.1) / 0.25 = 1.6분` = **96초**

웨이브 스테이지가 60초이므로, **S1 내에서는 50% 미도달** (최대 35%).
WaveDirector가 스테이지마다 리셋되므로, 매 웨이브 시작 시 10%에서 재시작.

**판정: PASS** -- 엘리트 확률이 웨이브 내에서 10%→35%로 점진 상승. 50% 캡에 도달하지 않아 all-elite 스웜 방지됨.

## I. 개선 제안 (코드 수정 미수행)

### FAIL-1: S6 boss_burst Phase 2 ATK 과다

**문제**: baseDamage 60 × stageMult 3.05 × phase2DamageMult 1.6 = 293. 기지 HP 잔여 350~450에서 1~2회 타격 즉사.

**제안** (`balance.ts`):

```typescript
// 현재
boss_burst baseDamage: 60
BOSS_PHASE.phase2DamageMult.boss_burst: 1.6

// 제안 A: 기본 데미지 하향
boss_burst baseDamage: 45  // 45 × 3.05 × 1.6 = 220 → 2~3회 생존

// 제안 B: Phase 2 배율 하향
BOSS_PHASE.phase2DamageMult.boss_burst: 1.3  // 60 × 3.05 × 1.3 = 238 → 2~3회 생존

// 제안 C: 보스 HP 캡과 유사하게 보스 ATK 캡 추가
DIFFICULTY.maxBossAtk: 200  // 새 필드
```

### FAIL-2: 미드 상점 경제 불일치

**문제**: `ECONOMY.shopCosts` (150~400)과 `MID_SHOP` 비용 (15~20)이 이중 시스템. S1 30초 시점 보유 ~120골드로 고가 상점 이용 불가.

**제안**:

```typescript
// 현재: ECONOMY.shopCosts.heal = 150
// MID_SHOP.healCost = 15

// 확인 필요: 실제 미드 상점 UI에서 어느 비용 테이블을 참조하는가?
// 만약 ECONOMY.shopCosts를 사용한다면:
ECONOMY.shopCosts.heal: 80   // 120골드 시점 구매 가능
ECONOMY.shopCosts.damage: 100
ECONOMY.shopCosts.armor: 100
```

### WARNING-1: S5 후반 난이도 급등

**제안**:

```typescript
// 현재
DIFFICULTY.hpScalePerMin: 2.2

// 제안: 시간 스케일링 완화
DIFFICULTY.hpScalePerMin: 1.8  // S5 60초: 5.06 × 1.8 = 9.11 (현재 11.13)
```

### WARNING-2: napalm 존 DPS 돌출

**제안**: 존 틱 데미지를 직격 데미지의 일정 비율로 조정하거나, 틱 간격을 늘림.

```typescript
// 제안: 틱 간격 750ms로 변경 → 5.3틱, DPS ~62 (현재 92.8)
// 또는 존 데미지를 직격의 50%로 감소
```

## J. M-014 보스+레벨업 소프트락 체크

코드 확인 결과, `ProgressionManager`에서 보스 사망 → `pendingStageClear` → 레벨업 처리 → 스테이지 클리어 순서가 직렬화되어 있음. M-014에서 수정된 것으로 보이나:

- 보스 XP(100~150)가 레벨업 XP 요구(고레벨 시 48~75)보다 높아 **매 보스전에서 이 경로가 실행됨**
- 보스 사망 + 다중 레벨업(XP 잔여로 2회 연속)이 발생할 수 있는지 추가 확인 필요

**판정: WARNING** -- 로직은 수정되었으나 매 보스전마다 이 코드 경로가 실행되므로, 회귀 테스트에 보스 사망 + 다중 레벨업 시나리오를 포함해야 함.
