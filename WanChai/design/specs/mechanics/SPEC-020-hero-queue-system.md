## 요약

히어로 대기열(Hero Queue/Grid)은 퍼즐 전투의 **핵심 전략 메카닉**이다. 플레이어는 원소별로 그룹핑된 2~4개 컬럼 중 어떤 컬럼에서 히어로를 배치할지 선택한다. 이 선택이 전투의 승패를 결정짓는 주요 인풋이다.

---

## 1. 데이터 구조

### 1.1 HeroGrid (2D 배열)

```
heroGrid: HeroInstance[][]
```

- 각 sub-array = 1개 **컬럼** (deployment column)
- 최소 2컬럼, 최대 4컬럼
- 컬럼의 index 0 = **선두 히어로** (배치 가능)
- 컬럼이 빈 경우 → 선택 불가 (UI에서 비활성)

### 1.2 제약 조건

| 항목 | 값 | 근거 |
|------|-----|------|
| 최소 컬럼 | 2 | 전략적 선택 최소 보장 |
| 최대 컬럼 | 4 | UI 공간 제약 (720px / 80px 셀 = 4) |
| 컬럼 내 정렬 | AP 내림차순 | 강한 히어로를 먼저 배치할 기회 |

---

## 2. 배치 메카닉

### 2.1 배치 규칙

1. 플레이어가 컬럼 N을 탭
2. 컬럼 N의 선두 히어로가 벨트에 진입 (FIFO: shift)
3. 다음 히어로가 선두로 승격 (UI 슬라이드 애니메이션)
4. 빈 컬럼은 탭 불가

### 2.2 슬링 콤보

연속 빠른 배치 시 스코어 보너스:
- 콤보 1: +10%
- 콤보 2: +20%
- 콤보 3: +30%
- 콤보 4: +40%
- 콤보 5: +50% (최대)
- 콤보 리셋: 배치 간 간격 > SLING_TAP_THRESHOLD_MS

### 2.3 게임오버 조건

| 조건 | 트리거 | 결과 |
|------|--------|------|
| 히어로 소진 | 모든 컬럼 빈 + 보드에 큐브 남음 | GAME OVER (no_heroes) |
| 벨트 만석 | 배치 시도 시 벨트에 6명 | GAME OVER (belt_full) |
| 벤치 만석 | 벤치 진입 시 5슬롯 모두 차있음 | GAME OVER (bench_full) |

## 3. 그룹핑 알고리즘 (buildHeroGrid)

### 3.1 클래식 모드

레벨 JSON의 `heroGrid` 필드를 직접 사용. 기획자가 수동으로 원소 배치.
`heroGrid` 미지정 시 `heroQueue`를 단일 컬럼으로 폴백.

### 3.2 로그라이크 모드

`buildHeroGrid()` 함수로 자동 생성:

1. **원소별 그룹핑**: Map<ElementColor, HeroInstance[]>
2. **AP 내림차순 정렬**: 컬럼 내 강한 히어로가 선두
3. **컬럼 수 조정**:
   - 원소 1종 → 2컬럼 (AP 기준 반분할)
   - 원소 2~4종 → 원소 수 = 컬럼 수
   - 원소 5~6종 → 4컬럼 (최소 그룹을 인접 그룹에 병합)
4. **컬럼 순서**: 보드에 가장 많은 원소의 컬럼이 앞쪽 (전략적 우선순위)

### 3.3 병합 규칙

5개 이상 원소 그룹 시:
1. 가장 적은 히어로를 가진 그룹부터 제거
2. 가장 적은 히어로를 가진 남은 그룹에 병합
3. 4그룹 이하가 될 때까지 반복
4. 병합된 컬럼은 AP 내림차순 재정렬

## 4. UI 표현

### 4.1 단일 컬럼 (≤1)

수평 히어로 라인. 선두 히어로 크게 표시, 뒤로 갈수록 작고 투명.

### 4.2 다중 컬럼 (2~4)

2D 그리드:
- 컬럼 헤더: 숫자 (1, 2, 3, 4)
- 선두 히어로: 80px, 글로우 보더, 펄스 애니메이션
- 후방 히어로: 72px, 점차 투명
- 빈 컬럼: 어두운 사각형 + "-"
