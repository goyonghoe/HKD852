# /qa-spec — 기획서 ↔ 코드 정합성

## 역할

QA 에이전트로서 기획 문서에 정의된 수치/로직이 코드에 정확히 반영되었는지 검증합니다.

## 절차

### 1. 기획서 수집

인자가 특정 스펙이면 해당 파일만, `all`이면 전체:

```
Glob: pattern "design/specs/**/*.md" path "WanChai/"
```

### 2. 스펙별 검증

각 기획서에서 추출할 항목:
- **수치 상수**: 대미지, HP, 속도, 쿨다운 등
- **로직 규칙**: "X이면 Y 발생", 조건 분기
- **UI 요소**: 표시해야 할 정보, 버튼, 게이지

### 3. 코드 매칭

기획서 수치를 코드에서 검색:

```
Grep: pattern "[수치/키워드]" glob "*.ts" path "src/"
```

- `balance.ts`, `weapons.ts`, `enemies.ts`에서 대응 상수 확인
- 씬 코드에서 로직 구현 확인

### 4. 차이 분류

| 분류 | 설명 | 심각도 |
|------|------|--------|
| 🔴 미구현 | 기획에 있으나 코드에 없음 | 높음 |
| 🟡 수치 불일치 | 기획 수치 ≠ 코드 수치 | 중간 |
| 🟢 기획 미반영 | 코드에 있으나 기획 문서에 없음 | 낮음 (문서 업데이트 필요) |

### 5. 결과 보고

```
📋 SPEC CONFORMANCE
────────────────────
검증 스펙:     N개
일치:          X개
차이 발견:     Y개
────────────────────
🔴 미구현 (기획 있음, 코드 없음):
  - [스펙명]: [항목]

🟡 수치 불일치:
  - [스펙명]: 기획 [A] vs 코드 [B]

🟢 문서 미반영 (코드 있음, 기획 없음):
  - [파일:줄]: [항목]
```

## 규칙

- 코드 수정하지 않음 (분석만)
- 수치 비교 시 ±5% 허용 오차 적용 (의도적 미세 조정 고려)
- numerical-bible.md 우선 참조
