온보딩 퍼널 설계 가이드

설치부터 Aha Moment까지 — 최초 실행 경험(FTUE) 마이크로 퍼널

HKD852 Studio | 2026-02-13 | v1.0 | 관련: 모바일서비스 퍼널전략 기초 가이드

개요

AAARRR 퍼널 가이드의 Activation 단계를 더 깊이 다루는 문서입니다. 앱 설치 후 첫 실행부터 튜토리얼 완료까지의 마이크로 퍼널을 단계별로 설계합니다.

왜 온보딩 퍼널이 중요한가? - 설치 후 첫 세션에서 50~70%의 유저가 이탈합니다
- 각 단계마다 5~30%씩 이탈이 발생하며, 이탈은 누적됩니다
- 온보딩 퍼널 최적화 없이 UA 비용을 늘리면 돈을 태우는 것과 같습니다
- 목표: 설치 유저의 70%+ 를 Aha Moment까지 도달시키기

핵심 원칙

원칙 설명
마찰 최소화 유저에게 가치를 제공하기 전에 요구하지 않는다. 모든 필수가 아닌 단계는 뒤로 미룬다.
가치 먼저 약관, 회원가입, 권한보다 핵심 경험을 먼저 보여준다.
탈출구 제공 모든 단계에 스킵/나중에 옵션을 제공한다. 강제하면 이탈한다.
진행감 표시 유저가 어디에 있고 무엇이 남았는지 보여준다. 불확실성은 이탈을 부른다.
즉각 피드백 모든 유저 행동에 시각적/청각적 즉시 반응을 제공한다.

전체 플로우

순서는 유연하게 위 플로우는 일반적인 순서이며, 장르/서비스 특성에 따라 순서를 바꿀 수 있습니다. 핵심은 가치 제공 전 마찰을 최소화하는 것입니다. 예를 들어 게스트 플레이를 먼저 제공하고 로그인/계정생성을 튜토리얼 후로 미루는 것이 일반적으로 더 좋은 전환율을 보입니다.

스플래시 구성 패턴

Good Pattern
  • 퍼블리셔 로고 1초 → 개발사 로고 1초 (total 2초)
  • 스플래시 중 필수 데이터 프리로드
  • 2회차부터 자동 스킵
  • 로고 페이드인/아웃 간결한 트랜지션
Bad Pattern
  • 엔진 로고 + 미들웨어 + 퍼블리셔 + 개발사 (4개, 8초)
  • 로딩은 별도 화면에서 다시 대기
  • 매번 스킵 불가
  • 과도한 애니메이션으로 3~5초 소요
팁: 스플래시를 로딩 시간으로 활용하세요 스플래시 표시 동안 뒤에서 네트워크 연결, 설정 파일 로드, 필수 에셋 프리로드를 수행하면 유저가 느끼는 대기 시간이 줄어듭니다.

로그인 화면 UI 가이드

  • 소셜 로그인: 플랫폼별 공식 버튼 가이드라인 준수
  • Apple Sign In: iOS에서 소셜 로그인 제공 시 Apple도 필수 (App Store 정책)
  • "나중에 로그인" 링크: 게스트 버튼이 없을 경우 반드시 제공
  • 비밀번호 입력: 최소 화면 전환, 자동 완성 지원

Pre-Permission 패턴 (권장)

시스템 팝업 전에 자체 UI로 먼저 설명하세요 1. 자체 팝업: "전투 결과를 알려드릴까요?" + 혜택 설명 + [허용] [나중에]
2. 유저가 [허용] 선택 시 → 시스템 권한 팝업 표시
3. 유저가 [나중에] 선택 시 → 시스템 팝업 표시 안 함 (기회 보존)

이유: iOS 시스템 팝업은 앱 당 1회만 표시됩니다. 거부하면 설정 앱에서만 변경 가능. Pre-Permission으로 허용률 +20~30%p 향상.
흔한 실수 - 첫 실행 시 알림+카메라+위치+연락처 한꺼번에 요청 → 공포감 → 전부 거부
- iOS ATT를 최초 실행에 요청 → 맥락 없이 거부 → 광고 수익 손실
- 권한 거부 후 기능 완전 차단 → "이 기능은 XX 권한이 필요합니다" + 설정 이동 안내 제공해야

원칙 방법 구현 예시

각 스텝 통과율이 90% 미만이면 해당 스텝에 마찰 요소가 있는 것입니다.
흔한 실수 - 5분 이상 강제 튜토리얼 → 핵심 재미 도달 전 이탈
- NPC 대사 스킵 불가 → "대사 다 읽어야 해?" → 이탈
- 실패 가능한 첫 전투 → 좌절감 → 이탈
- 모든 기능을 한번에 설명 → 정보 과부하 → 이탈
- 스킵 옵션 없음 → 재설치/경험자 이탈

9 Aha Moment — 핵심 가치 체험

목표: 설치 후 3분 이내 도달  |  누적 도달률: 70%+
70%+도달률
<3분도달 시간
D1 +15%p리텐션 영향

Aha Moment = 리텐션의 시작점

Aha Moment에 도달한 유저는 그렇지 않은 유저 대비 D1 리텐션이 15~25%p 높습니다. 온보딩 퍼널의 모든 단계는 유저를 이 순간으로 이끌기 위해 존재합니다.

장르별 Aha Moment 정의

장르 Aha Moment 도달 시간 목표
퍼즐 첫 레벨 클리어 + 별 3개 보상 1~2분
RPG 첫 스킬 사용 → 몬스터 처치 → 장비 획득 2~3분
전략 첫 건물 건설 완료 → 자원 생산 시작 3~5분
소셜 카지노 첫 빅윈 → 코인 폭발 연출 1분
하이퍼캐주얼 첫 스테이지 클리어 → 만족스러운 연출 30초
생산성 앱 첫 작업 완료 → 결과물 확인 2~3분
소셜 앱 첫 친구 추가 → 첫 메시지 수신 5분

Aha Moment 강화 기법

  • 감각 피드백 극대화: 화면 흔들림, 파티클, 효과음, 진동 (Haptic)
  • 과장된 보상: 첫 보상은 실제보다 화려하게 연출 (골드 비 내리기, 축하 배너)
  • 달성감: "축하합니다!" + 구체적 성과 ("3성 클리어!", "레벨 2 달성!")
  • 다음 목표 즉시 제시: "다음 도전: 보스 몬스터!" → 계속 플레이 유도

Aha Moment 이후 설계

Aha 이후가 진짜 시작입니다 1. 계정 연동 유도: "진행 상황을 저장하세요!" (게스트 유저 대상)
2. 푸시 알림 요청: 가치를 경험한 직후가 최적 타이밍
3. 다음 세션 예고: "에너지가 2시간 후 충전됩니다" / "내일 보상이 기다리고 있어요"
4. 핵심 루프 반복: 2~3번 더 핵심 루프를 체험시켜 습관화 시작
HKD852 에이전트 활용 - GameDesign_Agent /ux → Aha Moment 정의, FTUE 플로우 전체 설계
- GameDesign_Agent /balance → 튜토리얼 보상 밸런싱, 첫 경험 난이도
- GameDesign_Agent /monetize → 첫 과금 유도 타이밍 (Aha 이후)
