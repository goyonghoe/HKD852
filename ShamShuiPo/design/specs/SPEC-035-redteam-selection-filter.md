# SPEC-035 Red Team: Selection-Only Filter

> **작성**: Red Team Game Design Critic
> **날짜**: 2026-03-14
> **목적**: CEO의 "ZERO 컨트롤, SELECTION ONLY" 디렉션으로 SPEC-035의 5개 컨셉을 해부하고, 선택 기반 게임 설계 원칙을 수립한다.
> **CEO 디렉션 원문**: "가급적 컨트롤이 없었으면 좋겠어, 컨트롤은 선택만 있었으면 좋겠어, 컨트롤 요소를 최소화하고, 기대와 선택에 포커싱"

---

## CEO 디렉션 해석

"컨트롤"과 "선택"의 경계를 명확히 한다:

| 범주                   | 예시                                                                                               | CEO 판정 |
| ---------------------- | -------------------------------------------------------------------------------------------------- | -------- |
| **수동 컨트롤 (금지)** | 조이스틱 이동, 스와이프 방향 전환, 드래그 선긋기, 리듬 탭 타이밍, 블록 회전/배치, 재료 잡기        | X        |
| **선택 (허용)**        | 3개 중 1개 고르기, 배치할 위치 탭, 상점 아이템 구매, 빌드 방향 결정, 변환 여부 결정                | O        |
| **기대 (핵심)**        | 선택 후 결과를 지켜보기, 조합이 어떻게 터질지 예측, 드롭이 뭘지 기다리기, 빌드가 작동할지 두근거림 | O (핵심) |

**핵심 공식**: 플레이어는 **결정한다 (decide)**, 게임이 **실행한다 (execute)**. 플레이어의 손가락은 **"이것" 탭** 이상의 운동을 하지 않는다.

## Concept 1: 마작 서바이버 (Mahjong Survivor)

### 수동 컨트롤 위반 분석

| 인터랙션                            | 유형             | 문제                                 |
| ----------------------------------- | ---------------- | ------------------------------------ |
| 패를 위로 **플릭**                  | 수동 제스처      | 플릭 방향+속도 = 덱스터리티 요구     |
| 2~3장 **동시 플릭** (멀티터치)      | 수동 타이밍+위치 | 빠른 멀티터치 = 실시간 조작 기술     |
| **빠른 속도**로 패를 내는 것이 스킬 | 속도 기반 조작   | "판단 속도 자체가 스킬"이라고 명시됨 |
| 적이 접근할 때 **즉각 대응**        | 반사 신경        | 선택이 아니라 반응                   |

**수동 컨트롤 점수: 6/10** -- 패를 내는 행위 자체에 타이밍+제스처+멀티터치가 개입. 후반부 "패 회전이 미친듯이 빨라짐"은 완전히 반사신경 게임.

### 적응 가능성

**가능하다. 그리고 적응하면 더 좋아질 수 있다.**

적응 방법:

- 플릭 제거 --> 손패 5장이 화면에 나열, **탭으로 선택**
- 콤보 자동 감지: 같은 패 2장 이상 보유 시 "콤보 가능" 하이라이트 --> 탭 1회로 발동
- **역(役) 추구 선택**: 레벨업 시 "이번 런에서 노릴 역 레시피" 3개 중 선택 --> 이후 자동으로 해당 역 방향으로 패 우선 배치
- 전투는 **자동 진행**: 손패에서 탭한 패가 자동으로 최적 타이밍에 발동
- **핵심 전환**: "언제 내느냐"에서 "무엇을 노릴 것인가"로 무게중심 이동

잃는 것:

- 빠른 패 회전의 손맛, "판단 속도 = 스킬"이라는 레이어
- 적이 접근하는 긴박감 중 일부 (자동 전투가 흡수)

**판정: ADAPT** -- 마작의 핵심(조합 추구, 대기 vs 즉시 사용 트레이드오프)은 선택 시스템에 완벽 부합. 플릭은 표면적 장식.

## Concept 2: 네온 회로 (Neon Circuit)

### 수동 컨트롤 위반 분석

| 인터랙션                         | 유형            | 문제                                              |
| -------------------------------- | --------------- | ------------------------------------------------- |
| 손가락으로 **선 긋기 (드래그)**  | 정밀 수동 조작  | 이것이 게임의 핵심 인터랙션 그 자체               |
| 노드 사이 **정확한 연결**        | 공간 정밀도     | 작은 화면에서 엄지로 노드 연결 = 터치 정밀도 문제 |
| 회로 패턴 **형태**에 따른 보너스 | 기하학적 드로잉 | 삼각형, 벌집 등을 그리려면 정밀 드래그 필수       |
| **실시간** 회로 재건축           | 시간 압박+조작  | 보스가 회로 부수면 빠르게 재건 = 반사+정밀        |
| 더블탭으로 회로 삭제             | 위치 정밀 탭    | 특정 회로를 정확히 더블탭                         |

**수동 컨트롤 점수: 9/10** -- 게임의 존재 이유가 "선 긋기"라는 수동 조작. CEO 디렉션과 근본적으로 충돌.

### 적응 가능성

**극도로 어렵다. 선 긋기를 빼면 네온 회로가 아니다.**

적응 시도:

- 노드 연결을 "탭-탭" 자동 연결로? --> 그러면 "어떤 노드를 연결할지 선택"만 남음 --> 타워 디펜스의 타워 배치와 다를 바 없음 --> 차별화 소멸
- 프리셋 회로 패턴 3개 중 선택? --> 회로 설계의 창발성 소멸 --> 게임의 핵심 재미 제거

잃는 것:

- 게임의 정체성 전부. "플레이어가 세계를 직접 디자인한다"는 핵심 가치 제안이 사라짐.

**판정: KILL** -- 수동 조작이 게임의 DNA. 선택으로 전환하면 평범한 타워 디펜스로 전락하며, 그 시장은 이미 포화.

## Concept 3: 야식 연금술사 (Midnight Kitchen)

### 수동 컨트롤 위반 분석

| 인터랙션                         | 유형          | 문제                                    |
| -------------------------------- | ------------- | --------------------------------------- |
| **좌우 스와이프**로 활성 웍 전환 | 연속 스와이프 | 빠른 반복 스와이프 = 손가락 운동        |
| 떨어지는 재료를 **탭해서 배분**  | 반사+위치 탭  | 재료 낙하 속도가 빨라지면 반사신경 게임 |
| 웍을 위로 **플릭** = 즉시 요리   | 제스처        | 방향성 제스처 = 수동 컨트롤             |
| 웍을 아래로 **플릭** = 비우기    | 제스처        | 방향성 제스처                           |
| "재료가 빗발치는" 후반부         | 반사+속도     | "반사적 재료 분배가 핵심"이라고 명시    |

**수동 컨트롤 점수: 7/10** -- 스와이프+플릭+반사적 재료 잡기. Overcooked의 스트레스를 모바일로 옮긴 구조. 후반부는 완전한 반사 게임.

### 적응 가능성

**가능하지만, 근본적 재설계 필요.**

적응 방법:

- 재료 낙하를 제거 --> 대신 "재료 시장"에서 매 웨이브 시작 전 재료 세트 선택
- 요리 = 자동: 선택한 재료가 웍에 배분되고, 레시피에 맞으면 자동 요리 --> 자동 공격
- 선택 포인트: "이번 웨이브에 어떤 레시피를 노릴 것인가" + "어떤 재료 세트를 살 것인가"
- 대배당 상인 = 희귀 재료/레시피 선택

잃는 것:

- "주방이 바빠지는" 긴박감 전부. Overcooked의 카오스 에너지.
- 재료를 잡는 물리적 쾌감.
- 실시간 위기 관리의 스릴.

**판정: ADAPT (대폭 변형)** -- 요리+조합 시스템은 선택 기반에 적합하나, "바쁜 주방"이라는 핵심 판타지를 포기해야 함. 사실상 다른 게임이 됨.

## Concept 4: 비트 크래셔 (Beat Crasher)

### 수동 컨트롤 위반 분석

| 인터랙션                         | 유형           | 문제                                  |
| -------------------------------- | -------------- | ------------------------------------- |
| 비트에 맞춰 **탭**               | 타이밍 정밀도  | 리듬 게임의 본질 = 정확한 타이밍에 탭 |
| Perfect/Great/Good/Miss **판정** | 실시간 정밀도  | 0.1초 차이가 결과를 바꿈              |
| 방향 **스와이프**                | 방향+타이밍    | 상하좌우 방향 지정 = 수동 컨트롤      |
| **BPM 160+** 후반부              | 극한 속도      | 초당 3회 탭 = 완전한 덱스터리티 게임  |
| 콤보 유지 = 전투력               | 연속 정밀 입력 | 리듬감이 곧 게임 성과 = 스킬 기반     |

**수동 컨트롤 점수: 10/10** -- 리듬 게임은 정의상 타이밍 기반 수동 컨트롤이다. CEO 디렉션과 완전히 반대.

### 적응 가능성

**불가능. 리듬 게임에서 타이밍 탭을 빼면 리듬 게임이 아니다.**

적응 시도:

- 비트에 맞춰 자동 공격, 플레이어는 곡/무기만 선택? --> 그러면 음악 플레이리스트 앱.
- 비트 패턴을 사전에 선택? --> 그러면 DJ 시뮬레이터이지 전투 게임이 아님.

잃는 것:

- 게임 전체. 리듬 정확도 = 이 컨셉의 존재 이유.

**판정: KILL** -- 타이밍 기반 수동 입력이 장르의 정의. 선택으로 대체 불가.

## Concept 5: 네온 스택 (Neon Stack)

### 수동 컨트롤 위반 분석

| 인터랙션                           | 유형           | 문제                           |
| ---------------------------------- | -------------- | ------------------------------ |
| **좌우 스와이프**로 블록 위치 이동 | 연속 스와이프  | 정밀 위치 조정                 |
| **탭**으로 블록 90도 회전          | 반복 탭        | 빠른 연속 탭                   |
| **하단 스와이프**로 즉시 드롭      | 방향 제스처    | 타이밍+위치 결정을 동시에      |
| 블록 낙하 속도 증가 (0.8초/칸)     | 시간 압박      | 후반부는 완전한 반사 게임      |
| 방향별 줄 완성 전략                | 공간 판단+배치 | 어디에 놓을지 실시간 공간 판단 |

**수동 컨트롤 점수: 8/10** -- 테트리스의 핵심 = 블록을 원하는 위치에 원하는 방향으로 배치하는 공간 조작. 낙하 속도가 빨라지면 반사 게임.

### 적응 가능성

**부분적으로 가능하지만, 테트리스가 아니게 됨.**

적응 방법:

- 블록 배치를 자동화: 다음 블록의 **배치 위치 3곳**을 제안 --> 하나 탭으로 선택
- 또는 Columns 방식: 색상 순서만 탭으로 전환, 위치는 고정 열에 자동 낙하
- 줄 완성 시 공격 방향 선택 (상하좌우)

잃는 것:

- 테트리스의 "한 칸 차이로 끼워넣는" 정밀 배치 쾌감
- 공간 퍼즐의 자유도
- "테트리스 잘하면 강해진다"는 스킬 연결고리

**판정: ADAPT (대폭 변형)** -- 블록 쌓기의 전략성은 선택으로 전환 가능하나, 테트리스의 정체성은 소멸. "블록 기반 방어 선택 게임"이라는 다른 게임이 됨.

# PART 2: Selection-Only 설계 원칙

---

## 2.1 선택이 의미 있으려면: 10가지 규칙

### Rule 1: 불완전 정보의 원칙 (Imperfect Information)

**선택에 100%의 정보를 주지 마라.**

"화염 무기를 선택하시겠습니까?"보다 "??? 속성 무기 (힌트: 빨간 아이콘)"가 더 흥미롭다. Balatro의 조커 카드가 작동하는 이유 -- 효과를 완전히 이해하기 전에 선택하고, 결과를 확인하는 순간이 쾌감.

**구현**: 선택지의 30~70%만 공개. 나머지는 선택 후 밝혀짐. 리플레이할수록 정보 축적.

### Rule 2: 기회비용의 명시성 (Visible Opportunity Cost)

**"이걸 고르면 저걸 포기한다"가 보여야 한다.**

3개 선택지가 모두 좋아 보이면 의미 없다. 3개 중 2개는 "이걸 고르면 저 빌드 경로는 닫힌다"가 명확해야 한다. Slay the Spire에서 "Defect 카드 추가 vs 삭제 기회"가 agonizing한 이유.

**구현**: 선택 시 "이 선택으로 인해 닫히는 경로" 시각적 표시. 또는 자원이 유한하여 자연스럽게 트레이드오프.

### Rule 3: 컨텍스트 의존적 가치 (Context-Dependent Value)

**같은 선택이 상황에 따라 가치가 달라져야 한다.**

"체력 회복 +30%"은 체력 10%일 때와 90%일 때 완전히 다른 선택지다. 선택지의 절대 가치가 아니라 **현재 상태 대비 상대 가치**가 의사결정을 만든다.

**구현**: 선택지 자체는 고정이지만, 게임 상태(HP, 빌드, 적 구성, 보스까지 남은 시간)에 따라 최적 선택이 달라지는 구조.

### Rule 4: 지연된 결과 (Delayed Payoff)

**선택 직후가 아니라, 2~3분 뒤에 결과가 드러나야 한다.**

즉각 보상은 도파민 스파이크를 주지만 **기대감(anticipation)**을 만들지 못한다. "이 조합이 보스전에서 터질까?"라는 2분간의 두근거림이 CEO가 말하는 "기대"의 핵심.

**구현**: 선택 --> 효과 축적 --> 트리거 조건 충족 시 폭발. 중간에 축적 과정이 시각적으로 보여야 함 (게이지, 파편 수집 등).

### Rule 5: 되돌릴 수 없는 선택 (Irreversible Commitment)

**선택은 번복 불가능해야 한다.**

"나중에 바꿀 수 있어"는 선택의 무게를 제거한다. 로그라이크가 강력한 이유 -- 런 안에서 선택은 영구적. 잘못된 선택도 "이번 런의 이야기"가 된다.

**구현**: 런 내 선택 번복 불가. 단, 메타 진행으로 "다음 런에서 더 나은 선택지 풀"을 해금.

### Rule 6: 시너지 발견의 보상 (Synergy Discovery Reward)

**개별 선택보다 선택들의 조합이 더 강력해야 한다.**

A 선택 = 좋음. B 선택 = 좋음. A+B = 개사기. 이 "개사기" 조합을 **발견하는 순간**이 게임의 최고 순간. Balatro에서 특정 조커 조합이 점수를 기하급수적으로 올릴 때의 아하!

**구현**: 숨겨진 시너지 조합 풀. 발견 시 화면 전체 이펙트+사운드로 강조. 도감에 기록.

### Rule 7: 선택 빈도의 골디락스 (Goldilocks Selection Frequency)

**너무 자주도, 너무 드물지도 않게.**

- 너무 자주 (5초마다): 결정 피로 --> 아무거나 탭 --> 의미 소멸
- 너무 드물게 (5분마다): 중간에 할 것이 없음 --> 이탈
- 최적: **30~50초에 1회** 의미 있는 선택 + 중간에 자동 전투의 시각적 보상

**구현**: 주요 선택은 30~50초 간격. 그 사이는 이전 선택의 결과를 관전하는 시간.

### Rule 8: 위험 수용도 선택 (Risk Appetite Selection)

**안전한 선택과 위험한 선택이 공존해야 한다.**

- 안전: 확실한 +10% 데미지
- 위험: 50% 확률로 +50% 데미지, 50% 확률로 -20%
- 이 구조가 **플레이어의 성격을 게임플레이에 반영**시킨다.

**구현**: 모든 선택지 풀에 최소 1개의 "하이리스크-하이리턴" 옵션.

### Rule 9: 선택의 점진적 복잡화 (Progressive Selection Complexity)

**첫 선택은 2개 중 1개, 마지막 선택은 조건부 트레이드오프.**

- 1분: "불 무기 vs 얼음 무기" (단순)
- 5분: "DPS +30% vs 방어 +50%, 단 현재 빌드가 근접형이면 DPS가 더 가치있고..." (맥락 의존)
- 9분: "보스 실드 파쇄용 파편 비축 vs 지금 콤보 변환으로 잡몹 소탕" (전략적 딜레마)

**구현**: 시간 경과에 따라 선택지의 조건 분기가 증가.

### Rule 10: 선택의 서사화 (Narrative Selection)

**선택이 "내 빌드의 이야기"를 만들어야 한다.**

런이 끝나고 "이번엔 화염 마작 역에 올인했다가 보스전에서 금룡 파편이 뜨는 바람에 급히 전환해서 간신히 잡았다"라는 이야기가 만들어져야 한다. 선택의 연쇄가 **고유한 내러티브**를 생성.

**구현**: 런 종료 화면에 "이번 런의 핵심 선택 3개" 요약 표시. 공유 가능.

## 2.2 선택 기반 게임을 죽이는 5가지 안티패턴

### Anti-Pattern 1: 명백한 최적해 (Obvious Best Choice)

**증상**: 선택지 3개 중 항상 하나가 객관적으로 우월하다.

**왜 치명적인가**: 선택이 아니라 IQ 테스트가 된다. "이걸 안 고르면 바보"인 선택지가 있으면 나머지 2개는 존재 의미가 없다. 플레이어는 2~3런 만에 "항상 A를 고르면 됨"을 학습하고 선택에 무관심해진다.

**현실 사례**: 초기 VS에서 특정 무기(Garlic, King Bible)가 압도적으로 우월했던 시기 -- 레벨업 선택이 "가릭 나올 때까지 리롤"로 전락.

**방지법**:

- 밸런스 매트릭스: 모든 선택지의 상황별 기대값이 +-15% 이내
- 메타 시프트: 시즌/업데이트마다 선택지 강도 변동
- 카운터 시스템: A가 강하면 A를 카운터하는 적이 등장

### Anti-Pattern 2: 정보 없는 추측 (Uninformed Guessing)

**증상**: 선택을 위한 판단 근거가 전혀 없다. "빨간 문 vs 파란 문"인데 뒤에 뭐가 있는지 0% 힌트.

**왜 치명적인가**: 선택이 아니라 **동전 던지기**가 된다. 기대감은 "결과를 예측할 수 있을 때" 생긴다. 완전한 랜덤 앞에서는 기대감이 아니라 **무관심**이 생긴다.

**현실 사례**: 일부 로그라이크에서 이벤트 선택지가 완전 불투명 --> 플레이어가 wiki 없이는 플레이 거부.

**방지법**:

- 최소 30%의 정보 공개 (Rule 1의 역)
- 이전 런의 경험이 다음 런의 판단 근거가 되는 구조
- 시각적 힌트 (색상, 아이콘, 크기로 대략적 방향 암시)

### Anti-Pattern 3: 결과 무감각 (Result Numbness)

**증상**: 선택을 해도 화면에서 달라지는 게 없다. 숫자만 바뀜.

**왜 치명적인가**: 뇌는 추상적 수치 변화를 "보상"으로 인식하지 않는다. "데미지 +15%"를 선택했는데 화면에서 체감 변화가 없으면, 선택한 보람이 0.

**현실 사례**: 아이들 게임에서 업그레이드 클릭했는데 DPS 숫자만 올라가고 시각적 변화 0 --> "그래서 뭐?"

**방지법**:

- 모든 선택에 **즉각적 시각 변화** 동반 (투사체 색상, 크기, 이펙트, 사운드)
- 작은 선택도 화면에서 "뭔가 달라졌다"가 보여야 함
- 숫자 표시는 부차적, 시각/청각 변화가 1차적

### Anti-Pattern 4: 선택 과부하 (Selection Overload)

**증상**: 한 화면에 7개 이상의 선택지. 또는 5초마다 선택 요구.

**왜 치명적인가**: **Hick's Law** -- 선택지 수가 로그적으로 결정 시간을 증가시킨다. 7개 선택지 = 4.5초 결정 시간. 이것이 5초마다 오면 게임이 아니라 **업무**. 플레이어는 패턴을 찾아 자동화하거나(항상 첫 번째 선택), 이탈한다.

**방지법**:

- 한 번에 최대 3개 선택지 (예외적으로 4개)
- 선택 간 최소 20초 간격
- 연속 선택이 필요하면 중간에 결과 관전 시간 삽입

### Anti-Pattern 5: 가짜 선택 (Illusory Choice)

**증상**: 3개 선택지가 있지만 결과가 사실상 동일.

**왜 치명적인가**: 플레이어가 "어차피 뭘 골라도 똑같다"는 것을 깨닫는 순간, 게임에 대한 신뢰가 붕괴한다. 이후 모든 선택이 무의미해지고, "이 게임은 내 결정을 존중하지 않는다"는 배신감.

**현실 사례**: 일부 내러티브 게임에서 대화 선택지가 3개지만 결말은 동일 --> 플레이어 분노.

**방지법**:

- 모든 선택지는 **측정 가능한 다른 결과**를 만들어야 함
- 선택 결과의 차이가 즉시 or 2분 이내에 체감되어야 함
- 선택 기록을 보여주어 "내 선택이 런을 만들었다" 확인

## 2.3 기대감 스펙트럼 (The Anticipation Spectrum)

CEO가 "기대"를 강조했다. 선택과 결과 사이의 **시간적/심리적 간격**이 기대감을 만든다.

### 기대감의 5단계 모델

```
[선택] --> [축적] --> [예감] --> [트리거] --> [폭발]
  |          |          |          |           |
 0초       5~20초    20~40초    40~50초     50~60초
  |          |          |          |           |
"이걸    "모이고     "거의    "지금이다!"  "!!!!"
 골랐다"   있다..."   다 됐다..."
```

### 단계별 설계

**1. 선택 (0초)**: 3개 중 1개 탭. 선택 순간의 촉감 피드백 (진동, 사운드). "결정했다"는 확인감.

**2. 축적 (5~20초)**: 선택의 효과가 서서히 축적되는 것이 **눈에 보인다**. 게이지가 차오르거나, 파편이 모이거나, 이펙트가 점점 커진다. 이 단계에서 플레이어는 "내 선택이 작동하고 있다"를 확인한다.

**3. 예감 (20~40초)**: 축적이 임계점에 가까워지면 시각/청각 신호가 강화된다. 화면 테두리가 빛나거나, BGM이 빌드업. 플레이어의 심박이 올라간다. **"곧 터진다"를 알지만 정확히 언제인지 모르는** 상태가 최고의 기대감.

**4. 트리거 (40~50초)**: 조건 충족. 플레이어에게 "지금 발동?" 탭 1회 제공 (또는 자동). 이 찰나의 판단 -- "지금 쓸까, 보스까지 참을까" -- 이 마지막 미시적 선택이 기대감의 정점.

**5. 폭발 (50~60초)**: 화면 전체 이펙트. 3초간의 슬로우모션. 적이 쓸려나감. 데미지 숫자 폭포. **축적된 기대감이 한 순간에 해소되는 카타르시스.**

### 기대감을 극대화하는 연출 기법

| 기법                | 설명                                   | 예시                                             |
| ------------------- | -------------------------------------- | ------------------------------------------------ |
| **슬로우 빌드업**   | 효과가 점진적으로 강해지다 폭발        | 파편이 하나씩 합체 --> 빛 --> 폭발               |
| **니어미스 테이저** | "거의 됐는데 안 됨"을 1~2회 경험시킴   | 3파편 콤보 2/3 상태에서 다른 파편 드롭 --> "아!" |
| **카운트다운 텐션** | 시각적 카운트다운                      | 보스 실드 HP 바가 깎이다 마지막 1칸              |
| **음악 싱크**       | BGM이 기대감 단계에 동기화             | 축적 시 조용 --> 예감 시 빌드업 --> 폭발 시 드롭 |
| **화면 줌**         | 폭발 직전 살짝 줌아웃 --> 폭발 시 줌인 | 숨을 들이쉬는 듯한 카메라                        |

## 2.4 모바일 세로 모드 (Portrait) 제약 조건

### 화면 구역 분할

```
┌─────────────────────┐
│   정보 구역 (15%)    │  HP, 점수, 타이머
│                     │
│                     │
│   관전 구역 (50%)    │  전투 자동 진행
│                     │  이펙트, 적, 드롭
│                     │
│                     │
├─────────────────────┤
│   선택 구역 (35%)    │  선택지 표시
│   [A]  [B]  [C]     │  큰 터치 타겟
│                     │
└─────────────────────┘
```

### 선택 UI 제약

| 항목                | 제한                              | 이유                           |
| ------------------- | --------------------------------- | ------------------------------ |
| 동시 선택지 수      | **최대 3개** (예외적 4개)         | Hick's Law + 터치 타겟 크기    |
| 터치 타겟 최소 크기 | **48x48pt** (Apple HIG 기준 44pt) | 엄지 탭 정확도                 |
| 터치 타겟 간격      | **최소 8pt**                      | 오탭 방지                      |
| 선택지 위치         | **화면 하단 35%**                 | 한 손(왼손 엄지) 도달 범위     |
| 선택 시간 제한      | **3~5초** (자동 선택 있음)        | 관전 흐름 중단 최소화          |
| 선택지 정보 표시    | **아이콘 + 1줄 텍스트**           | 빠른 인지. 긴 설명 = 읽기 거부 |

### 한 손 조작 도달 범위 (왼손 엄지 기준, iPhone 15 Pro Max)

```
┌─────────────────────┐
│ ███████████████████ │  <-- 도달 불가 (상단 15%)
│ ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓ │  <-- 어려움 (상단 15~30%)
│ ░░░░░░░░░░░░░░░░░░ │  <-- 보통 (중단 30~60%)
│                     │
│ ████████████████████│  <-- 편안함 (하단 60~100%)
│ ████████████████████│
│     [A] [B] [C]     │  <-- 최적 선택 위치
└─────────────────────┘
```

**핵심**: 선택 버튼은 반드시 **화면 하단 40%** 영역에 배치. 정보 표시는 상단에서 가능하지만, 인터랙션은 절대 상단에 두지 않는다.

## 3.1 선택 기반 게임 시장 현황

### 오토배틀러 시장

| 지표                       | 현황                                    |
| -------------------------- | --------------------------------------- |
| TFT 월간 활성 유저         | 3,300만 명 (2025~2026 유지)             |
| TFT 2025 e스포츠 상금 총액 | $4.2M                                   |
| Auto Chess류 신작          | 연 10~15개 (2022 피크 대비 감소)        |
| 시장 판정                  | **성숙기 -- 성장은 멈췄지만 죽지 않음** |

오토배틀러는 "피로(fatigue)"보다 **"안착(settled)"**에 가깝다. TFT가 독점적 위치를 차지하며 시장이 고착. 신작이 진입할 틈은 있으나, TFT와 정면 경쟁은 자살행위. **차별화된 PvE 오토배틀러**가 빈 자리.

### 아이들/인크리멘탈 시장

| 지표                        | 현황                                    |
| --------------------------- | --------------------------------------- |
| 2024 시장 규모              | $2.4~2.5B                               |
| 2033 전망                   | $5.6~6.1B (CAGR 9.8~10.8%)              |
| 수익 구조                   | 광고 60~70%, IAP 30~40%                 |
| 아케이드 아이들 월 다운로드 | Top 50 합산 6,000만+                    |
| 시장 판정                   | **성장 중 -- 하이브리드 아이들이 견인** |

아이들 게임은 놀랍게도 아직 성장 중이다. 핵심은 **하이브리드 아이들** -- 순수 클리커가 아니라 아이들+아케이드, 아이들+RPG, 아이들+TD 같은 결합형이 시장을 끌고 있다. 선택 기반 로그라이크는 이 시장의 "아이들+전략" 교집합에 위치할 수 있다.

| 지표                      | 현황                                |
| ------------------------- | ----------------------------------- |
| Steam 등록 수             | 1,157개 (2026 기준)                 |
| Steam 합산 매출           | $84M                                |

적나라한 진실: Steam에 1,157개의 로그라이크 덱빌더가 있고, 합산 매출이 $84M이라는 것은 **평균 매출이 $72K**라는 뜻이다. 상위 10개 게임(StS, Balatro, Monster Train 등)이 전체 매출의 대부분을 차지하고, 나머지 1,147개는 $10K도 못 버는 경우가 대다수.

"매일 새 로그라이크 덱빌더가 얼리 액세스로 나오고, 대부분 같은 짓을 한다" (PC Gamer). 하지만 Slay the Spire 2가 역대 최대 기록을 세운 것을 보면, **장르 자체에 피로가 있는 것이 아니라 평범한 게임에 피로가 있는 것**이다.

| 총 판매           | 500만+ 카피 (2025.1 기준)                           |

| 수상              | GDCA 2025 GOTY, Best Design, Best Debut, Innovation |

**Balatro가 작동한 진짜 이유 (레드팀 분석):**

1. **보편적 규칙 기반**: 포커 핸드를 전 세계가 안다. 학습 비용 0초. 하지만 실제로는 포커가 아님 -- "포커를 해킹하는" 재미.

2. **선택 = 게임 전체**: Balatro에는 수동 컨트롤이 없다. 카드 선택, 조커 선택, 핸드 선택이 전부. **CEO 디렉션의 완벽한 선례.**

3. **기대감 설계의 교과서**: 카드를 내기 전에 "이 핸드에 이 조커가 적용되면..." 하고 점수를 머릿속으로 계산하는 순간이 **기대감의 정수**. 선택 --> 결과 사이에 **점수 계산 애니메이션**이라는 서스펜스가 삽입됨.

4. **숫자의 기하급수적 스케일**: 100점 --> 1,000점 --> 100,000점 --> 10,000,000점. "거지에서 신으로"의 성장 서사가 **숫자 자체**로 체현됨.

5. **스트레스 제거**: HP 시스템 없음. 실패 = 점수 부족일 뿐. "거의 됐는데!" 좌절이 아니라 "다음엔 더 높이!" 동기.

6. **$9.99 프리미엄**: 광고/가챠 없이 순수 게임플레이로 승부. 이것이 평론가+유저 동시 호감을 만듦.

## 3.2 "선택 기반 로그라이크"는 시장성이 있는가?

### 정직한 평가

**결론: 가능하다. 하지만 좁은 바늘구멍을 통과해야 한다.**

#### 가능한 이유

1. **Balatro가 증명했다**: 선택 기반(수동 컨트롤 0) 로그라이크가 500만 카피 팔릴 수 있다. 시장 수요가 존재한다.

2. **모바일 최적**: 선택 기반은 한 손 조작에 완벽. 출퇴근길, 침대에서, 한 손에 커피 들고. "열심히 탭하는" 게임이 아니라 "생각하고 한 번 탭하는" 게임.

3. **하이브리드 아이들 시장과 교집합**: 선택 기반 로그라이크는 아이들 게임의 "관전 쾌감"과 로그라이크의 "빌드 깊이"를 결합. $2.5B 아이들 시장의 상위 세그먼트를 노릴 수 있다.

4. **스트리머/유튜버 적합**: Balatro가 보여줬듯, "선택의 과정"이 관전 콘텐츠로서 매력적. 선택 기반 게임은 시청자가 "나라면 B를 골랐을 텐데!" 하며 참여 가능.

#### 위험한 이유

1. **Balatro 한 방울 효과**: Balatro의 성공이 장르 전체의 성공을 의미하지 않는다. Vampire Survivors가 650+ 클론을 낳았지만 대부분 실패한 것처럼, "선택 기반 로그라이크"도 상위 3~5개만 생존할 것.

2. **차별화 압박**: "마작+로그라이크", "포커+로그라이크"... 다음은 뭐? "XX+로그라이크" 공식 자체가 포화. **조합의 신선함만으로는 부족**. 결합 방식의 혁신이 필요.

3. **수익화 난제**: Balatro는 프리미엄 $9.99. F2P로 가면 선택 기반 게임에서 IAP를 어디에 끼울 것인가? "더 좋은 선택지를 돈 내고 사기"는 P2W. "코스메틱"은 선택 화면에서 차별화가 어려움. **수익화 모델이 게임 디자인 단계에서 해결되어야 함.**

4. **"보기만 하면 지루해 보임" 문제**: 선택 기반 게임의 앱스토어 스크린샷/영상은 **정적**으로 보인다. 물량 학살 화면이 UA 소재로 강력한 VS/Survivor.io와 달리, "3개 카드 중 고르는 화면"은 광고 소재로 약하다.

## 3.3 최종 권고

### 레드팀의 냉정한 판단

1. **CEO 디렉션은 올바르다.** 선택 기반 게임은 모바일에서 미개척 영역이 남아있고, Balatro가 수요를 증명했다.

2. **5개 컨셉 중 마작 서바이버만 살아남는다.** 단, "서바이버"라는 이름에서 오는 "불릿헤븐" 기대는 조정 필요. 이것은 "마작 로그라이크"에 더 가깝다.

3. **SPEC-034 (네온 연금술) 역시 재검토 대상.** 조이스틱 이동 + 자동 공격이 핵심인 현재 설계는 CEO의 새 디렉션과 충돌. 네온 파편 콤보 시스템만 추출하면 선택 기반으로 전환 가능하나, 그러면 SPEC-034가 아닌 새 설계가 필요.

4. **"마작 역 + 네온 파편 콤보 + 자동 전투 관전"** 조합이 CEO 디렉션에 가장 부합하는 방향:
   - 마작의 역 추구 = 빌드 선택의 깊이
   - 네온 파편 = 보상 수집의 시각적 쾌감
   - 자동 전투 = 선택 결과의 관전 + 감각 포화
   - 이 셋을 합치면: **"적이 자동으로 죽으면서 네온 파편을 드롭 --> 파편으로 마작 역(빌드 조합)을 추구 --> 역 완성 시 화면 폭발"**

5. **수익화는 게임 디자인과 동시에 설계하라.** "나중에 F2P 훅을 넣겠다"는 실패 공식. Day 1부터 코스메틱 변환 이펙트, 역 레시피 도감 컬렉션, 시즌 역 레시피 등 수익화 구조가 코어 루프에 녹아있어야 한다.

6. **프로토타입은 Balatro를 벤치마크하라.** Phaser/Unity가 아니라 **종이 프로토타입**부터. 카드 3장 놓고, 주사위 굴려서 파편 뽑고, 역 레시피 카드 위에 배치. 60초 안에 "재미있다/없다"가 판단 가능해야 한다.
