# About Face UI/UX 원칙 — ShamShuiPo 적용 지침서

> Alan Cooper「About Face: The Essentials of Interaction Design」핵심 원칙을
> 모바일 불릿 헤븐 게임(720x1280, 9:16 포트레이트, 한 손 조이스틱) 맥락으로 번역한 프로젝트 전용 지침서.

---

## 원칙 1: 목표 지향 설계 (Goal-Directed Design)

> "사용자의 목표를 위해 설계하라. 기능을 위해 설계하지 마라."

플레이어는 "무기 8종의 DPS를 비교"하려는 게 아니라 **"수백 마리를 쓸어버리는 쾌감"**을 원한다.

### 체크리스트

- **[MUST]** 모든 화면은 "이 화면에서 플레이어가 얻는 감정"을 명시할 수 있어야 한다
- **[MUST]** 정보 화면(도감 등)도 단순 나열이 아닌, "발견의 즐거움"을 제공해야 한다
- **[SHOULD]** 기능 추가 전 "이것이 플레이어의 어떤 목표를 돕는가?" 질문할 것
- **[NICE]** 각 씬에 도달했을 때의 감정 목표를 주석으로 명시

---

## 원칙 2: 페르소나 (Personas)

> "평균적인 사용자는 없다. 구체적인 한 사람을 위해 설계하라."

### 핵심 페르소나: "민수" (28세, 서울, 직장인)

- 출퇴근 지하철에서 10분씩 플레이
- 한 손(엄지) 조작, 세로 모드로 잡고 플레이
- 조이스틱으로 이동, 공격은 자동 — 이동만 집중하면 됨
- 빠른 판단, 긴 튜토리얼 싫어함
- "화면 가득 적이 쏟아지는데 나는 살아남는다"는 서바이벌 쾌감에 몰입

### 체크리스트

- **[MUST]** 모든 터치 타겟 48dp 이상 (한 손 엄지 조작)
- **[MUST]** 조이스틱 영역과 다른 인터랙티브 요소 겹침 금지
- **[MUST]** 한 판(런) 10분 — 지하철 한두 정거장 간격
- **[SHOULD]** 인터랙션 1초 내 결과 확인 가능
- **[SHOULD]** 텍스트 설명보다 시각적 직관 우선

---

## 원칙 3: 멘탈 모델 (Mental Models)

> "인터페이스는 구현 모델이 아닌, 사용자의 멘탈 모델을 반영해야 한다."

플레이어 멘탈 모델: "적이 몰려온다 → 내가 피하면서 자동으로 쏜다 → 적을 죽이면 보석이 뜬다 → 모으면 강해진다 → 더 센 적이 온다"

### 체크리스트

- **[MUST]** 게임 메카닉이 멘탈 모델과 일치 (Kill → Collect → Upgrade 루프 명확)
- **[MUST]** 수치(DPS, CD, 배율)를 직접 노출하지 말고, 체감으로 전달
- **[SHOULD]** 코드 용어(defId, projectileType)가 UI에 노출되지 않을 것
- **[SHOULD]** 업그레이드 효과를 "수치 변경"이 아닌 "체감 변화"로 설명
- **[NICE]** "이 무기는 뭘 하는 건지" 3초 내 이해 가능한 시각적 힌트

---

## 원칙 4: 잉여 행위 제거 (Eliminating Excise)

> "목표 달성에 불필요한 인지적·물리적·시각적 노력을 제거하라."

### 3가지 Excise 유형

| 유형       | 정의                 | 예시                     |
| ---------- | -------------------- | ------------------------ |
| **인지적** | 불필요한 생각 요구   | "이 수치가 뭘 의미하지?" |
| **물리적** | 불필요한 탭/스와이프 | 돌아가려면 3번 탭        |
| **시각적** | 화면 정보 과잉       | 14px 텍스트 8줄 나열     |

### 체크리스트

- **[MUST]** 씬 전환 최소화: 2탭 이내에 원하는 화면 도달
- **[MUST]** 반복 동작 자동화 (자동 공격, 자동 수집, 자동 조준)
- **[MUST]** 불필요한 확인 팝업 제거
- **[SHOULD]** 한 화면에 7±2개 이하의 정보 단위
- **[SHOULD]** 돌아가기 버튼은 항상 같은 위치(화면 하단)
- **[NICE]** 스와이프로 뒤로가기 (플랫폼 관례)

---

## 원칙 5: 몰입(Flow) 보호

> "사용자의 몰입 상태를 방해하는 모든 것을 제거하라."

### 체크리스트

- **[MUST]** 전투 중 모달 팝업 최소화 (레벨업 선택은 빠르게)
- **[MUST]** 레벨업 선택지 3개 이하 (선택 마비 방지)
- **[MUST]** 보스 등장 = 긴장감 고조 (경고 → 화면 흔들림 → 등장)
- **[SHOULD]** 레벨업 중에도 배경에 적·투사체 보임 (맥락 유지)
- **[SHOULD]** 게임 일시정지 시에도 배경 일부 보임 (맥락 유지)
- **[NICE]** 연속 처치 시 점진적 BGM 강도 증가

---

## 원칙 6: 직접 조작 (Direct Manipulation)

> "오브젝트를 직접 조작하고, 결과를 즉시 확인할 수 있어야 한다."

### 체크리스트

- **[MUST]** 조이스틱 드래그 → 플레이어 즉시 이동 (입력 지연 0)
- **[MUST]** 업그레이드 선택 → 즉시 효과 체감 (무기 추가/변경, 탄 패턴 변화)
- **[SHOULD]** 도감에서 무기 탭 → 무기 발사 데모 보기
- **[SHOULD]** 레벨업 카드 위 미리보기로 효과 시각적 표시
- **[NICE]** XP 수집 시 보석이 플레이어에게 자석처럼 빨려오는 VFX

---

## 원칙 7: 피드백 & 가시성 (Feedback & Visibility)

> "시스템 상태를 항상 보여주고, 모든 인터랙션에 즉각 반응하라."

### 피드백 계층

| 계층               | 채널 | 예시                                   |
| ------------------ | ---- | -------------------------------------- |
| **1차 (즉각)**     | 시각 | 버튼 scale, 히트 플래시, 데미지 넘버   |
| **2차 (0.1~0.5s)** | 청각 | 타격음, 레벨업 징글, 보스 경고음       |
| **3차 (지속)**     | 상태 | HP 바, XP 바, 타이머, 무기 슬롯 쿨다운 |
| **4차 (선택)**     | 촉각 | 보스 등장 진동, 피격 진동              |

### 체크리스트

- **[MUST]** 모든 버튼에 시각 피드백 (press: scale 0.95)
- **[MUST]** 모든 적 처치에 시각+청각 피드백
- **[MUST]** 시스템 상태 항상 표시 (HP, XP, 타이머, 무기, 스테이지)
- **[SHOULD]** 보스 등장/사망에 특별 연출
- **[SHOULD]** 업그레이드 선택 후 "강화됨!" 시각 이펙트
- **[NICE]** 연쇄 처치 콤보 카운터 + 사운드 에스컬레이션

---

## 원칙 8: 일관성 (Consistency)

> "같은 것은 같게, 다른 것은 다르게 보여라."

### 체크리스트

- **[MUST]** 모든 씬에서 동일한 버튼 스타일 (ButtonFactory 단일 소스)
- **[MUST]** 모든 패널 코너 라디우스 통일 (12px)
- **[MUST]** 색상은 colors.ts에서만 (hex 매직 넘버 금지)
- **[MUST]** 폰트 크기 체계: 48/32/22/16/14px만 사용
- **[SHOULD]** "돌아가기" 버튼 위치·크기·스타일 모든 씬에서 동일
- **[SHOULD]** 씬 전환 애니메이션 통일 (fade 500ms)

---

## 원칙 9: 모드리스 인터랙션 (Modeless Interaction)

> "모드를 최소화하고, 모드가 필요할 때는 명확히 표시하라."

### 체크리스트

- **[MUST]** 현재 모드 시각적 표시 (playing, levelup, paused 등)
- **[MUST]** 모드 전환 시 명확한 시각 변화 (배경 어둡게, 패널 등장)
- **[SHOULD]** 레벨업 모달 진입 시 게임 슬로우모션 → 정지 (부드러운 전환)
- **[SHOULD]** 모든 모드에서 "나가기" 방법이 명확할 것
- **[NICE]** 게임 중 일시정지 없이 설정 변경 가능 (인라인 컨트롤)

---

## 원칙 10: 오류 예방 (Error Prevention)

> "오류를 처리하기보다 애초에 불가능하게 설계하라."

### 체크리스트

- **[MUST]** 골드 부족 시 구매 버튼 비활성화 (탭 불가)
- **[MUST]** 최대 레벨 도달 시 업그레이드 카드 시각적 잠금
- **[SHOULD]** 실수 구매 방지: 고가 아이템에 확인 단계
- **[SHOULD]** "되돌리기"가 가능한 설계 > 확인 팝업
- **[NICE]** 비파괴적 탐색: 도감 탭은 어떤 상태도 변경하지 않음

---

## 원칙 11: 앱 포스처 (Application Posture)

> "소버린 앱은 풍부한 피드백과 고밀도 정보를 제공한다."

Neon Survivors = **소버린 포스처** (전체화면, 반복 사용, 높은 몰입)

### 체크리스트

- **[MUST]** 전체 화면 활용 (720x1280 전체)
- **[MUST]** 풍부한 시각 피드백 (파티클, 데미지 넘버, 히트 플래시)
- **[MUST]** 상태 정보 상시 표시 (HUD)
- **[MUST]** HUD 요소 화면 가장자리에서 최소 16px 마진
- **[MUST]** 인접 HUD 요소 간 최소 8px 간격
- **[SHOULD]** 컨텍스트 도구 (탭 위치에 따라 다른 반응)
- **[SHOULD]** BGM + SFX로 분위기 몰입 강화
- **[NICE]** 화면 여백 최소화, 정보 밀도 높이기

---

## 원칙 12: 점진적 공개 (Progressive Disclosure)

> "처음에는 핵심만 보여주고, 깊이는 탐색할 때 공개하라."

### 체크리스트

- **[MUST]** 첫 플레이 시 1개 무기만 제공. 나머지는 플레이하며 획득
- **[MUST]** 도감: 미조우 항목은 실루엣("???")으로 표시
- **[SHOULD]** 첫 런에서는 HUD 최소화, 2~3런 후 전체 HUD 공개
- **[SHOULD]** 업그레이드 선택지: 현재 빌드에 관련 있는 것 우선 표시
- **[NICE]** 첫 보스 조우 시 특별 연출 (한 번만)
- **[NICE]** 새 무기 획득 시 "신규!" 뱃지 + 짧은 소개
