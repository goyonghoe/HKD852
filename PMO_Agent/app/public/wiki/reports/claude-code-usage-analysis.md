## 1. 사용 패턴 프로파일

### 1-1. 커뮤니케이션 스타일

Kowloon의 지시 방식은 **극도로 간결하고 맥락 의존적**이다.

| 특징       | 예시                              | 의미                                         |
| ---------- | --------------------------------- | -------------------------------------------- |
| 최소 지시  | "음, 또 안되는데"                 | 문맥에서 대상을 추론하도록 위임              |
| 액션 우선  | "파일 경로 열어주세요 전달하"     | 설명보다 즉시 실행 선호                      |
| 한/영 혼용 | "iOS 시뮬레이터 앱을 올리라고"    | 기술 용어는 영문 유지                        |
| 위임 신뢰  | "충분히 시간을 써서 고민해주시고" | 결과물 품질에 대한 높은 기대치 + 자율성 부여 |

이 스타일은 Claude Code와의 시너지가 매우 높다. 불필요한 설명을 생략하고, AI가 메모리/맥락에서 의도를 추론하도록 맡기는 것은 **고급 사용자의 전형적 패턴**이다.

### 1-2. 도메인 전환 속도

단일 세션에서 관찰된 작업 도메인 **7개**:

```
인프라 디버깅 → 도구 공유 → 게임 기획 문서화 → 뉴스 수집 →
앱스토어 전략 → 플랫폼 심사 → 자기 분석 요청
```

| 도메인                     | 깊이   | 소요 비율 | 비고                  |
| -------------------------- | ------ | --------- | --------------------- |
| 인프라 디버깅 (Monitor)    | 깊음   | 35%       | 근본 원인까지 추적    |
| 게임 기획 (Score HTML)     | 중간   | 20%       | 변환 작업 위임        |
| 뉴스 수집 (/ai-news-daily) | 자동화 | 15%       | 스킬 호출로 완전 위임 |
| 앱스토어/플랫폼            | 얕음   | 10%       | 질문-답변 형식        |
| 도구 공유/기타             | 얕음   | 5%        | 즉시 완료             |
| 자기 분석                  | 깊음   | 15%       | 종합 보고서 요청      |

깊이가 필요한 곳(디버깅, 분석)과 빠른 답변이 필요한 곳(전략 질문)을 직관적으로 구분하고 있다.

## 2. 강점 분석

### 2-1. 체계화 본능 (★★★★★)

Kowloon의 가장 두드러진 강점은 **경험을 시스템으로 변환하는 능력**이다.

| 시스템            | 규모                      | 효과                  |
| ----------------- | ------------------------- | --------------------- |
| 실수 레지스트리   | 20건, 5개 파일            | 같은 실수 재발 방지   |
| 메모리 시스템     | 7개 토픽 파일 + MEMORY.md | 세션 간 컨텍스트 유지 |
| 에이전트 조직     | 21명, 106 스킬            | 복잡한 작업 위임 체계 |
| 템플릿 라이브러리 | 24종 HTML                 | 산출물 품질 일관성    |
| 칸반 파이프라인   | 7개 스킬 + 배포           | 프로젝트 관리 자동화  |

이 정도 수준의 체계화는 Claude Code 사용자 중 **상위 1%** 수준이다. 대부분의 사용자는 CLAUDE.md 하나로 운영하지만, Kowloon은 **다층 메모리 + 실수 레지스트리 + 자동 품질 파이프라인**을 구축했다.

### 2-2. 위임 설계 능력 (★★★★☆)

AI 에이전트에 대한 위임은 매우 효과적이다:

- **오케스트레이터 패턴**: 모든 요청을 자동 라우팅 (/orchestrator)
- **품질 체인**: Quality Gate → Shield → RedTeam 3단계 자동 검증
- **배치 최적화**: 칸반 배포를 배치 단위로 묶어 비용 절약
- **스킬 파이프라인**: /shorts-factory, /paper-factory 등 E2E 자동화

그러나 **자기 자신에 대한 위임**은 약하다. 50개 태스크 나열 후 전부 직접 하려는 경향이 관찰된다.

### 2-3. 실패 학습 속도 (★★★★★)

실수 레지스트리를 보면 **동일 실수의 재발 빈도가 거의 0**이다:

- `#1` TTS 다국어 → v4.3~v4.5에서 11가지 근본 원인 전부 수정
- `#10` 배포 누락 → 원커맨드 체인으로 구조적 해결
- `#14` JSON 동기화 → cp 명령을 체크리스트에 고정
- `#20` normalizeTask → 데이터 파이프라인 전체 체크 규칙 수립

한 번 실수하면 **"왜?"를 5번 물어서 근본 원인까지 추적**하고, 재발 방지 시스템을 만든다. 시니어 엔지니어의 포스트모텀 문화와 동일한 패턴이다.

### 2-4. UX 감각 (★★★★☆)

- Score formula → "다들 어려워해요, 쉽게 만들어주세요" (팀원 관점 사고)
- JA 음성 4라운드 20+ 샘플 청취 후 선택 (품질 타협 없음)
- 자막 max_chars 언어별 최적화 (KO:16, EN:25, JA:14)
- 모바일 가독성 우선 원칙

## 3. 개선 영역

### 3-1. 태스크 눈덩이 (위험도: ★★★★☆)

```
한 세션에서 7개 도메인 → 각 도메인에서 후속 태스크 파생 →
후속 태스크가 다음 세션의 우선순위와 경쟁 → 이월 태스크 누적
```

**구조적 해결 제안**:

1. 세션 시작 시 **"오늘의 TOP 3"** 명시적 선언
2. 새로운 요청이 TOP 3 밖이면 → 백로그에 기록만 (즉시 실행 안 함)
3. 금요일 `/vault-weekly`에서 이월 태스크 강제 정리

### 3-2. 배포-검증 갭 (위험도: ★★★☆☆)

실수 레지스트리에서 가장 빈번한 카테고리:

| 실수 # | 요약                 | 공통 원인                          |
| ------ | -------------------- | ---------------------------------- |
| #10    | 배포 안 하고 보고    | "완료 = 코드 수정"이라는 인식      |
| #13    | 칸반 미반영          | 배포 체크리스트 스킵               |
| #14    | JSON 동기화 누락     | 수동 동기화 의존                   |
| #19    | 라이브 미검증        | "배포 성공 = 동작 확인"이라는 가정 |
| #20    | 파이프라인 부분 수정 | 전체 체인 사고 부족                |

5건 중 4건이 **"코드를 고치는 것"과 "사용자에게 도달하는 것" 사이의 갭**에서 발생한다.

**구조적 해결 제안**:

- `kanban-deploy` 스킬의 검증 단계를 모든 배포에 확대 적용
- 배포 완료 기준: `curl` + JS 번들 키워드 확인까지가 "완료"
- 장기적으로 CI/CD에 배포 후 스모크 테스트 자동화

### 3-3. 데이터 레이어 문제 (위험도: ★★★★☆)

JSON 파일 기반 데이터 관리가 프로젝트 규모를 따라가지 못하고 있다:

| 프로젝트      | 데이터 저장               | 문제점               |
| ------------- | ------------------------- | -------------------- |
| PMO 칸반      | JSON + Blob + cp 동기화   | 3곳 수동 동기화 필요 |
| Saju          | API 키 미설정 → 데모 폴백 | DB 미구축            |
| ShortsFactory | JSON 스크립트 파일        | 에피소드 관리 불편   |

**제안**: 다음 새 프로젝트부터 **Supabase(PostgreSQL) 우선** 적용. 기존 PMO 칸반은 리팩토링 ROI가 낮으므로 현행 유지.

### 3-4. 에너지 관리 (위험도: ★★★☆☆)

7개 도메인을 한 세션에서 처리하는 것은 인상적이나, 지속 가능성 관점에서:

- **인프라 디버깅**은 CEO가 직접 할 필요 없음 (DevOps_Agent 위임 가능)
- **뉴스 수집**은 이미 자동화됨 (/ai-news-daily)
- **앱스토어/플랫폼 질문**은 비서실장에게 조사 위임 가능

**실제로 CEO가 해야 할 것**: 의사결정, 방향 설정, 품질 승인
**위임 가능한 것**: 리서치, 디버깅, 문서 변환, 배포

## 4. 시너지 최적화

### 4-1. 현재 시너지 구조

```
CEO (방향 + 판단) → Claude Code (실행 + 체계화) → 에이전트 조직 (전문 작업)
```

### 4-2. 즉시 적용 가능한 개선

#### A. "생각 파트너" 활용도 높이기

현재 Claude Code를 주로 **실행자**로 사용하고 있다. 하지만 **전략적 사고 파트너**로도 활용할 수 있다:

- 의사결정 전 다관점 분석 (`/debate-synthesize`)
- 새 시장 진입 전 리서치 + 비판적 평가
- 주간 회고에서 패턴 발견

#### B. 선제적 알림 시스템

현재 메모리 시스템은 **수동 참조** 방식. 자동화 가능한 항목:

| 항목                | 현재               | 제안                             |
| ------------------- | ------------------ | -------------------------------- |
| 좀비 프로세스 (#11) | 메모리에 규칙 있음 | 세션 시작 훅으로 자동 스캔       |
| 이월 태스크 경고    | 미구현             | 2주 이상 이월 건 자동 표시       |
| 에너지 체크         | 미구현             | 시간대 기반 (야간/주말) 알림     |
| 미결 의사결정       | 미구현             | Vault 03_Decisions 자동 리마인드 |

#### C. Agent Teams 적극 활용

메모리에 "독립 파일 수정 3개 이상이면 Agent Teams로 병렬 처리" 규칙이 있으나, 실제로는 순차 실행이 기본인 세션이 많다. **습관화** 필요.

#### D. Kowloon이 Claude Code에 바라는 것

| 영역             | 현재                 | 개선                          |
| ---------------- | -------------------- | ----------------------------- |
| 배포 검증        | 요청 시만 수행       | 모든 배포 후 자동 검증        |
| 태스크 관리      | 요청받은 것만 처리   | TOP 3 초과 시 백로그 제안     |
| 에너지 체크      | 프로필에 규칙만 존재 | 야간/주말 작업 시 실제로 언급 |
| 전략 제안        | 과거 지식 의존       | 항상 최신 리서치 선행         |
| 멀티 도메인 전환 | 수동 전환            | 도메인 간 연결점 선제 제안    |

## 6. 단계별 학습 제안

### Phase 1: 기반 강화 (지금 ~ 4월)

**목표**: 현재 시스템의 약한 고리를 보강하고, 이미 만든 규칙들을 습관화한다.

| #   | 학습 항목                  | 방법                                                              | 기대 효과              |
| --- | -------------------------- | ----------------------------------------------------------------- | ---------------------- |
| 1   | **"TOP 3" 세션 시작 의식** | 세션 시작 시 "오늘 TOP 3"을 선언하고, 초과 요청은 백로그에만 기록 | 태스크 눈덩이 50% 감소 |
| 2   | **배포 = 검증 포함** 습관  | 배포 후 curl 검증을 "완료"의 정의에 포함                          | 배포 관련 실수 0건     |
| 3   | **Agent Teams 기본값화**   | 3개 이상 독립 파일 수정 시 자동으로 팀 구성 제안                  | 작업 시간 30% 단축     |
| 4   | **주간 의사결정 정리**     | 금요일 `/vault-weekly` + 미결 결정 목록 리뷰                      | 결정 지연 감소         |

### Phase 2: 확장과 위임 (4월 ~ 6월)

**목표**: CEO 역할을 "실행"에서 "감독"으로 더 이동시킨다.

| #   | 학습 항목                       | 방법                                                           | 기대 효과          |
| --- | ------------------------------- | -------------------------------------------------------------- | ------------------ |
| 5   | **인프라 작업 위임**            | DevOps 이슈는 먼저 DevOps_Agent에 위임, 해결 안 되면 직접 개입 | CEO 시간 20% 회수  |
| 6   | **리서치-의사결정 분리**        | 리서치는 에이전트에 위임, CEO는 결과만 보고 판단               | 의사결정 품질 향상 |

| 8   | **Obsidian Vault "두 번째 뇌"** | 모든 의사결정, 주간 리뷰를 Vault에 축적 → 패턴 분석            | 장기 인사이트      |
