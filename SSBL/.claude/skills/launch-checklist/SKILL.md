# /launch-checklist — SSBL 런칭 체크리스트 관리

## 목적

SSBL D-30 전시 모드 런칭 체크리스트(68개 태스크)의 상태를 추적하고, Go/No-Go 자동 판정을 제공합니다.

## 데이터 소스

- **JSON 데이터**: `SSBL/data/launch-checklist.json` (상태 업데이트 대상)
- **원본 Excel**: `SSBL/design/SSBL_런칭체크리스트_20260224-115603.xlsx` (3개 시트: 작성 기준, 대시보드, 런칭 체크리스트)

## 핵심 원칙 (작성 기준 시트에서)

- **"뭘 할지"가 아니라 "뭘 안 할지"를 결정하는 도구**
- 완벽 포기, 생존 확보. "치명적 사고 없는 런칭"이 목표
- 마감일은 주 단위 X → **일 단위** ("3월 셋째 주"가 아니라 "3월 17일 EOD")
- 정렬 기준: 구분(P0→P1→P2) → 마감일 순. 카테고리별 정렬 금지

## 3단계 분류

| 구분      | 태스크 | 의미                                                    |
| --------- | ------ | ------------------------------------------------------- |
| [P0] 필수 | 21개   | 미완료 시 런칭 불가. 스토어 심사, 결제, 서버, 법적 의무 |
| [P1] 중요 | 27개   | 첫인상 훼손. 튜토리얼, 버그, 번역, 이벤트               |
| [P2] 후속 | 20개   | 출시 후 1~2차 업데이트에서 대응                         |

## 담당자 상태

| 상태      | 의미                          | 대응                               |
| --------- | ----------------------------- | ---------------------------------- |
| 이름 명시 | 확정. 매일 진행 상황 확인     | -                                  |
| 인수필요  | 레거시 담당자 퇴사/이동       | 48시간 내 재배치, 못하면 포기 검토 |
| 미정      | 아무도 안 잡음. **가장 위험** | 즉시 배정                          |
| 포기      | 한 달 안에 불가능 합의        | 런칭 후 로드맵에 명시              |

## Go/No-Go 판정

| 판정               | 조건                                                 |
| ------------------ | ---------------------------------------------------- |
| **GO**             | [P0] 100% 완료 + [P1] 80%+ 완료 + [P0] 담당 미정 0건 |
| **CONDITIONAL GO** | [P0] 100% + [P1] 60~80% + D+3 핫픽스 플랜            |
| **NO-GO**          | [P0] 미완료 건 존재                                  |

## 서브커맨드

### 현황 조회 (기본)

```
/launch-checklist
/launch-checklist status
```

### 상태 업데이트

```
/launch-checklist update <task_no> <상태>
```

상태: `미착수` | `진행중` | `완료` | `블로킹` | `포기`

### 담당자 배정

```
/launch-checklist assign <task_no> <담당자명>
```

### 마감일 설정

```
/launch-checklist deadline <task_no> <YYYY-MM-DD>
```

### 대시보드 HTML 생성

```
/launch-checklist dashboard
```

### Go/No-Go 판정

```
/launch-checklist gonogo
```

## 실행 절차

1. `SSBL/data/launch-checklist.json` 읽기
2. 서브커맨드 처리
3. 변경 시 JSON의 `meta.updated` 갱신
4. 대시보드 생성 시 `SSBL/outputs/launch_dashboard_YYYYMMDD.html` 출력

## Excel 수정 시 주의 (인수인계 사항)

### 폰트 오염 방지 순서 (필수)

```
1. 용어/데이터 변경 (openpyxl)
2. 수식 재계산 (LibreOffice recalc)
3. 폰트 수정 (openpyxl) ← 반드시 recalc 이후
4. 저장 (recalc 다시 돌리지 않음)
```

### 용어 매핑 (수식 조건값 포함)

| 변경 전          | 변경 후   |
| ---------------- | --------- |
| [BLOCK] 런칭차단 | [P0] 필수 |
| [QUAL] 런칭품질  | [P1] 중요 |
| [POST] 런칭후    | [P2] 후속 |
| Tier             | 구분      |
